# ADR 0002：S1 最小用户数据导出与隔离恢复

日期：2026-10-19；状态：S1 导出/恢复部分已交付（S1 草稿/稳定提交由前端任务交付）；适用范围：本地 v0.1 开发与手工备份。

## 背景

S1 要求“刷新/失败后草稿可恢复、未知网络结果不生成新操作 ID”，并在最终发布前先提供人工导出/恢复。阶段一核验也指出：历史上“持久化探针”不能当作备份恢复演练。S2 才引入离线 outbox 与多端同步，因此本阶段不做双向合并或自动备份。

## 决定

1. **导出是白名单、只读、可校验的 JSON**。`GET /api/v1/export` 与 `pnpm export:data` 共用 `packages/db/src/backup.ts`；只导出当前用户的事实/定义/变更日志/幂等回执，不导出会话、凭据、AI 生成任务与批次审计。导出带 `format`、`schema_version`、`contract_version`、迁移清单、行数、同步游标与 SHA-256 校验和。
2. **恢复是显式 CLI，不是公开写接口**。`pnpm restore:data --file <path>` 只在目标库为空、迁移清单完全一致时执行单个事务；校验和、主键/外键、行数任一失败即回滚。默认拒绝开发库，必须显式 `--allow-development`。
3. **保留历史与幂等语义**。软删除记录写入墓碑，`record_revisions`、`change_log`、`mutation_receipts` 随备份恢复；这样恢复后旧客户端重放同一 `Idempotency-Key` 不会重复生成事实。会话不恢复，客户端需重新登录。
4. **不把导出当同步**。没有设备游标、outbox、ack 或冲突合并；S2 的同步协议必须独立设计，不能以“导入备份”代替。

## 备选与否决

- 使用 `pg_dump/pg_restore`：直接、完整，但绑定容器/版本与宿主路径，无法在 API 内做用户级校验和；仍可作为后续运维级备份，不替代本阶段的用户级导出。
- 导出后自动写回开发库：会覆盖真实数据，风险高；否决。
- 把备份文件放浏览器下载并自动导入：缺少隔离与回滚保证；本阶段只做下载按钮，恢复保留在 CLI。

## 后果与限制

- 备份文件含个人记录，必须自行保管；单文件大小、流式导出和大数据量恢复未优化。
- 自动备份调度、保留期限、异机副本、恢复演练与告警仍属 T4/T5。
- 恢复后的一致性由事务与计数校验保证；派生统计不重算，因为定义/事实/授予按原版本恢复。若后续迁移改变派生规则，需在迁移流程中重算并记录版本。
