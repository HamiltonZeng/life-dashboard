# 本机合成性能测量

Docker aarch64、8 核、约 7.75 GiB；Node v24.22.0，PostgreSQL 18 固定镜像。每组合成 100/1000/10000 条已确认记录与 101/365 个任务实例；单条手动 daily 模板及一个合计数值。经过 API 注入走真实鉴权/服务/PG，计时包含 HTTP handler/JSON 和 SQL，未包含外部浏览器网络延迟。每项 3 次，无外部模型或下载。

表格为中位毫秒 / SQL 次数。SQL 包括会话查询、BEGIN/COMMIT；每次客户端 query 真实计数，不是推算。完整样本见 [performance-samples.json](performance-samples.json)。事实写入每次建立新记录，并走完整重算与回执，不是只测 INSERT。

旧实现模板/实例装饰按每项查询，列表先加载全部 DTO 再筛分页，同 Client 并发 query 产生驱动弃用警告。现模板列表一条主体 SQL，任务分页先 count/筛选/分页，再批量读取至多 50 个 DTO；主页只装饰最终五项；资格/最近流水和系列里程碑批量取数。以上规模 SQL 数保持稳定，完整日志未再出现同 Client 并发查询警告。

第一轮测得 10k 年趋势约 1.58–2.73 秒，主要为每天全扫事实及每条来源做线性 find。改为按当地日期分组、ID 索引后，在相同规模重测为亚秒级（精确 3 次样本见 JSON）；32 组旧冻结引擎输出对照通过，覆盖四范围、四聚合、两时区和来源版本，另有原全部粒度/null/0/日等权/排除规则测试。

这是少量本机样本，不是 p95、压力上限或并发 SLA。手动模板场景没有模拟 365 个复杂自动聚合模板；模板物化仍在单用户事务内顺序执行，复杂规则/大量模板会增加事务时长。保持本版本简单性，不加入队列或缓存。真实个人库、网络丢包/资源受限设备和长期生产负载未做性能承诺。
