# 第一阶段阻断问题与交接

日期：2026-10-20。被测业务基线 `f3203a7`。本报告由 Codex 代执行 DeepSeek 任务产生；没有通过另一模型或独立人员复核。

## DS-01：合法业务字段 session 被浏览器草稿保护误拦截

优先级：P1，阻断 P1-02。所有者：Gemini 前端。后端同名资料字段与真实记录模板均可通过合法 Schema，不是 API 拒绝业务 key。

实际复现 B01：通过真实 API 创建包含 `key=session,type=text` 的记录模板 → Chromium 打开记录面板 → 选该模板 → 填写学习时段 → 点击保存。页面显示 `LOCAL_STORAGE_FAILED` / “未保存本机”，records 中该合成业务值数量为 0。

预期：业务 `values.session` 可以像其他受限业务值一样持久草稿并提交；认证 DTO 的 Cookie/口令/token 等结构字段仍不能被写入草稿。

源码核对：`apps/web/src/storage.ts:52` 的 SENSITIVE_KEY 包含 session，`hasSensitiveKey` 对所有对象递归检查，未区分 values 业务域与认证结构。字段名匹配后 writeJson 返回失败，记录表单按保护逻辑不发请求。

证据：`browser.json:B01` observations 为 persisted_records=0、storage_error_visible=1；`B01.png` 显示合法输入和错误。没有通过删除凭据保护或放宽验收绕过问题。

修复后需重跑：B01 成功保存、刷新可恢复，认证属性仍拒绝；B10 的真实存储故障不发送边界继续通过。新增专门断言验证凭据不进入新配置持久化 DTO，不能只测试文本中包含敏感词。

## DS-02：配置创建丢回执后重试更换操作键和实体 ID

优先级：P1，阻断 P1-03。所有者：Gemini 前端。后端 D03/D06 的原键/原包重放通过。

实际复现 B02：Chromium 填写新模块名称 → 拦截 POST `/api/v1/modules`，先 `route.fetch()` 让服务器完整提交，再 `route.abort()` 丢弃浏览器回执 → 同一表单再次点击提交。两次服务器请求完成后读取结果：请求数=2、Idempotency-Key 不同、模块 ID 不同、同名模块数量=2。

预期：第二次确认沿第一次操作键、实体 ID、完整冻结载荷重放，服务器只保留一个配置对象；刷新后仍能确认旧操作，用户修改的新输入单独保留。

源码核对：`apps/web/src/main.ts:1831` 每次调用 createModule 没有传持久化操作键/ID；`api.ts:82` 和 `api.ts:201` 在缺省时分别生成新键和新实体 ID。原记录的冻结包逻辑没有扩展到配置创建。

证据：`browser.json:B02` 记录两组不同键/ID 与 modules_with_same_name=2，`B02.png` 保留错误后的表单。浏览器夹具明确等待两次 route.fetch/abort 完成后计数，避免把还未提交的请求误计成无重复。第一次整体验收后补强了这一同步，并定向复跑全部 10 个浏览器场景，重复模块数量稳定为 2。

当前 B02 在原键断言失败，后续的“编辑当前草稿→刷新→恢复旧操作”代码已准备但没有执行到，不能宣称已验收。修复所有配置创建路径（不只模块）后需分别验证模块、模板、任务、数值、成就的原包冻结、刷新恢复、编辑后确认旧操作、损坏回执及存储失败不发送。当前自动复现以模块为代表，未将其余四类路径算作通过。
