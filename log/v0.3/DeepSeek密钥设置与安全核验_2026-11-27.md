# DeepSeek 密钥设置与安全核验

本机 v0.3 在「设置 → AI 连接与授权 → DeepSeek API 密钥」提供保存、更换和删除。保存或删除需要已登录会话和当前本地登录口令。保存后状态只显示是否已配置。应用的 API 与后台 worker 从同一本机密钥库读取，通常无需重启。保存密钥本身不会请求 DeepSeek 或新增模块授权。已授权模块和已启用的报告日程可能使用保存的密钥。

## 安全范围

| 场景 | 实现与结果 |
| --- | --- |
| 浏览器与权限 | 密码框无回填，提交不走草稿或操作回执。接口要求单用户会话、二次口令和正确来源，对修改请求限速。网页代理保留浏览器来源，并检查密钥接口的 Host |
| 本机存储 | 密钥使用带认证的 AES-256-GCM 加密，写入时使用随机 nonce 和原子替换。密文在版本运行数据目录，主密钥在单独的私有目录，通过只读挂载提供给容器。两个文件均要求仅所有者可读写 |
| 数据边界 | API 状态和业务备份不返回密钥。配置请求不进入聊天、数据库或操作回执，登录及密钥接口关闭常规请求日志 |
| 对外发送 | 网页录入的密钥仅用于 DeepSeek 官方 HTTPS API 的 Authorization 请求头，拒绝跟随重定向。发送的数据范围仍由模块授权控制 |
| 删除 | 删除本机密钥后，服务端下一次调用重新读取配置并拒绝发起请求。已发出的请求无法召回，删除本机文件也不会吊销 DeepSeek 平台上的密钥 |
| 部署限制 | 由网站管理密钥只在回环地址配置下启用。若使用服务器环境变量提供密钥，由环境配置管理。当前 Docker 只向宿主机回环地址开放网页，API 在容器内监听回环地址 |

这套设计适用于当前单人本机部署。能访问 Docker、控制本机用户账户或同时取得主密钥与密文的人仍可读取密钥。浏览器扩展也可能读取输入框。业务备份不含密钥，整机文件备份仍可能覆盖私有目录。若密钥泄露，需要到 DeepSeek 平台吊销。迁移到 VPS 前需设计 HTTPS、访问控制和服务端密钥管理。

## 验证

- v0.3 专项 129 项、前端逻辑 9 项及 19 组渲染检查通过。专项覆盖跨来源、无会话、错误口令、非本地部署拦截、文件权限、加密内容、状态接口与业务备份，以及网关使用和删除后停止发送。
- Edge Chromium 连接隔离 Docker 实例，确认可保存、刷新、更换和删除，错误口令和跨来源提交被拒绝。页面、浏览器存储、服务日志未出现合成密钥。
- 正式环境运行 `life-dashboard:v0.3-local-credentials`，沿用原有数据库和登录口令。正式容器验证了登录、读取、私有主密钥文件权限与状态。未写入真实 DeepSeek 密钥，也未发起真实模型调用。

实现位于本机部署所用的 `v0.3/.runtime/deploy-2026-11-27/source/v0.3`，证据在同一部署目录的 `credential-checks/`。原启动入口 `v0.3/.runtime/deploy-2026-11-27/start-local.sh` 已选择新增密钥设置的镜像。

## 输入框修复

旧镜像中，从密钥框切到本地口令框时遇到后台同步，整页重绘会替换输入框，导致密钥消失。修复后，同一账号停留在设置页时，设置卡片和整页重绘均复用原密码输入元素。离开设置或开始提交时清除未提交输入，浏览器持久存储不参与保留。

在 Edge Chromium 中先复现旧镜像的清空，再用相同步骤验证修复。后台刷新前后两个输入都保留，光标仍在口令框，离开设置后重进为空。保存、更换、删除与权限回归通过。修复镜像 `life-dashboard:v0.3-local-credentials-focus-fix` 已在本机健康运行，并通过登录和业务读取检查。
