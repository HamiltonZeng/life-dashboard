# 人生面板开发日志 · 2026-11-25

**这版可以创建计划、记录活动并查看报告。有两处日常操作卡住了：网页下不了备份文件，极简首页也没有直接返回按钮。** 这两类问题在上次合并前就已存在。

## 上次究竟改了什么

11 月 21 日 21:19（北京时间），维护者将 [PR #3](https://github.com/HamiltonZeng/life-dashboard/pull/3) 合并进主分支。对使用者来说有三处变化。

- 打开「设置」看 AI 连接状态时，如果服务已配置但尚未授权读取模块，页面会提示你勾选至少一个模块并保存。「服务器连接配置与用量」里能看到模型和思考模式。
- 当模型拒绝不支持的请求参数时，程序会停下来报错。模型返回的内容格式不对时，程序只在允许的范围内再试，必要时给出失败提示。
- 生成计划和报告时，程序把固定说明和每次输入的内容分开传送，有利于供应商复用相同的说明。本次没有测量真实账户的缓存命中率、费用或速度提升。

你提供的 `teamwork.zip` 交接包记录，上次第一轮审核发现问题，第二轮修正了 4 处，隔离数据库的 138 项检查和网页的 19 组检查通过。当时本机镜像也重新构建过，真实 DeepSeek 调用仍待验证。交接包记录提交 PR 时的状态是「待合并」。11 月 25 日查 GitHub，状态已经变成「已合并」。

我核对了 PR 作者提交的完整文件树和合并到主分支的文件树，两者完全相同。共 9 个文件的改动都在。GitHub 上这次合并当时没有自动检查记录，所以这次另外开了独立测试环境复核。[合并提交](https://github.com/HamiltonZeng/life-dashboard/commit/7120d0c94f1a5314547838fd496780d661555290)

## 我实际点了什么

使用没有个人数据的新数据库，向程序提供模拟的 AI 回复。网页、应用服务、数据库和浏览器都实际运行。桌面按 1440 × 900 检查，手机按 360 × 800 模拟。

| 你会怎么用 | 本次看到的结果 |
| --- | --- |
| 打开首页，再进任务、记录、数值、成就和设置 | 桌面和手机共检查 12 个页面组合，都能打开，每页有标题，两种尺寸都没有整页横向滚动。个人资料和钱包入口也能进入 |
| 让它安排每天学英语 20 分钟 | 浏览器拿到已保存的计划。新建计划时不会凭空产生学习记录 |
| 告诉它今天跑了 3 公里，再把距离纠正为 2 公里 | 第一次产生一条记录。纠错时能看到改动，确认后原记录更新为 2 公里，相关奖励也按测试规则冲回 |
| 查看原话、修改资料、撤销 | 来源可以点开。测试资料 60 → 65，确认撤销后恢复 60，刷新仍是 60 |
| 看任务、数值、成就和代币 | 隔离测试验证了记录推动进度、数值和奖励。无记录的日期与记录为 0 的日期能够区分，撤销有对应流水 |
| 生成日报、周报、月报，设置自动日报 | 三类报告都能在浏览器打开。开启安排需要确认一次，确认后能关闭 |
| 输入一段话后刷新，或遇到结果不明再提交 | 浏览器用例验证草稿恢复。另有用例验证重试沿用原请求，不重复创建记录或重复发放奖励 |
| 点「设置 → 账户与数据 → 导出数据」 | **失败。** 服务器返回成功，并已生成第 3 版备份。网页只接受第 1 版，提示「不支持的导出数据版本 3（当前支持 1）」。两种屏幕都收不到下载文件。数据库恢复测试通过 |
| 切到首页极简模式，再刷新 | **部分通过。** 模式能保存，页面仍多出报告表单，首页没有直接退出按钮。两种屏幕都能通过「设置 → 显示与反馈 → 恢复标准首页」返回 |

### 为什么常规测试都通过，还能发现问题

常规网页逻辑检查有 19 组、143 条断言，四组 Node 测试分别通过 9、42、91、112 项，合计 254 项。浏览器还走通了真实页面上的计划、记录、纠错、资料、报告与日程。备份和极简首页另用浏览器从按钮开始测试。原检查会分别核对服务器导出和单个首页组件，完整网页组装后还能出错。[常规验证](https://github.com/xmdongju/life-dashboard/actions/runs/45621037925) · [现版界面专项](https://github.com/xmdongju/life-dashboard/actions/runs/45621248360)

第一轮运行旧版测试时使用了普通用户模式，旧 AI 测试依赖开发模式，产生 21 项失败。改用项目原本为这组测试指定的开发模式后，91 项全部通过。网页冒烟继续采用普通用户模式。这里修正的是测试配置。

### 这两个问题是不是上次 PR 引入的

我在合并前的版本用相同步骤重新打开桌面和手机页面。相同的导出版本提示、报告表单和缺失的直接退出按钮都能复现。这三处相关行为早于 PR #3。[合并前对照](https://github.com/xmdongju/life-dashboard/actions/runs/45621697847)

## 版本和运行状态

截至本次核验，上游仓库查不到 `v1.0` 标签或同名正式发布。本次测试用合并后的源码新建了独立环境。仓库的默认启动命令会复用本机已有镜像，单独更新 Git 代码后，正在运行的容器是否更新还要看镜像的构建版本。

## 现在如何处理

| 优先级 | 要做什么 | 用户什么时候算用得上 |
| --- | --- | --- |
| 先修 | 让网页接受服务器生成的有效备份版本；在极简首页放回退出按钮，并移走报告表单 | 点一次导出即可拿到可恢复文件；退出极简只需一步 |
| 接着做 | 首页把今日任务放到输入框下面，记录后能直接回到来源 | 打开就知道今天要做什么、刚记的东西在哪里 |
| 后续做 | 整理数值、报告、成就和设置的布局与用词 | 手机上能看清趋势、找到依据、读懂 AI 提示 |

本次验证的是真实 Chromium 与隔离数据库。AI 供应商使用模拟回复，未调用收费模型；没有测试实体手机、真实手机键盘或使用者电脑上的运行镜像。项目默认启动已有本地镜像，是否包含合并代码取决于该镜像何时重建。详细的页面布局、代码落点和验收顺序见[前端升级方案](../../design/v0.5/前端升级方案.md)。
