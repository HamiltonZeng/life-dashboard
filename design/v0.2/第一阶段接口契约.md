# v0.2 第一阶段接口契约（协作输入 1.0）

本文件冻结三方开始并行所需的产品接口；**端点和 Schema 由 Codex 后续实现，当前不声称可调用**。修改须协调并更新同一份文档。应用版本 v0.2 不等于现有 `CONTRACT_VERSION=0.2.0`；是否提升契约版本由实现负责人统一决定。

## 通用写入

- 继续 `/api/v1`、当前 Cookie/Origin 和本地单用户边界，不由客户端提交可信 user_id。
- 写入带 `Idempotency-Key`；更新带 `base_version`；成功 `{data: ..., operation_id: ...}`。profile/preferences 响应均有 `id`（用户 UUID）及正整数 `version`。
- 同键同载荷重放返回原结果；不同载荷 409；校验失败 400/422；版本冲突 409，不隐式覆盖。
- 模型、奖励报价、兑换能力仍未开放，直接调用相应受控写路径返回 `409 FEATURE_DISABLED`，不产生任务/事实/余额副作用。
- 新写入必须通过统一变更/修订/回执体系，不新建绕过事务的简单 JSON 覆盖端点。

## GET /api/v1/profile

`data`：

```json
{
  "id": "user-uuid",
  "version": 1,
  "nickname": "用户已设置的昵称",
  "bio": null,
  "timezone": "Asia/Shanghai",
  "static_avatar_ref": null,
  "module_fields": []
}
```

没有配置时返回真实默认用户信息与空字段集合，不自动生成个人事实。nickname 长度 1–60，bio 可空且最多 1000；timezone 为 IANA 时区。`static_avatar_ref` 本阶段只读 null，不实现上传/3D。

`module_fields` 每项包含 `id,module_id,key,label,type,kind,value,unit,options`。kind 本阶段只允许 `profile`；type 使用既有受限字段类型，value 符合该类型或 null。Decimal 使用十进制字符串；日期为 ISO 日期。key 与模块内唯一性由服务端校验，允许合法业务 key `session`，不能因名似凭据而误拒业务值。

## PATCH /api/v1/profile

`{base_version,nickname?,bio?,timezone?,field_upserts?: [...],field_remove_ids?: [...]}`。

字段 upsert 使用客户端 UUID 和上述字段结构；已存在字段修改沿用其 ID，删除必须显式列出 ID。不含的字段保持原样；昵称/简介空值的语义明确区分“未传”与 null。时区修改不重写历史记录或指标已有时区。

只允许本人模块字段，归档模块不新增可编辑资料。`kind=observation|derived` 及记录/累计统计/代币修改在本阶段拒绝，不能按 profile 直接落成事实。整包变更原子执行并保留修订。

## GET / PATCH /api/v1/home-preferences

GET `data`：

```json
{
  "id": "user-uuid",
  "version": 1,
  "minimal_mode": false,
  "pinned_metric_ids": [],
  "pinned_task_ids": [],
  "pinned_trends": []
}
```

PATCH：`{base_version,minimal_mode?,pinned_metric_ids?,pinned_task_ids?}`。数组顺序就是首页顺序；不能重复或引用其他用户对象。建议最大固定数值 4、任务 5；超限明确 422，不静默截断。最简模式开关不清空 pin 数组。

`pinned_trends` 为未来预留，第一阶段必须为空且不可写。周期模板 pin 也暂不开放，当前 pin 使用 v0.1 单次任务实例 ID。归档/删除对象不得造成页面崩溃，读取时返回或排除失效引用并提供可解释提示。

## GET /api/v1/home

只读首页组合，`data` 包含：`cursor,profile,preferences,metrics,tasks,recent_achievements,wallet,avatar`。

- profile/preferences 与来源数据带版本，采用一致读取，不能取不同时间快照却冒充一致。
- metrics 复用现有指标及 computed，包含单位、统计周期、来源与 null/0 语义；优先按固定顺序。
- tasks 由当地今日任务与固定任务去重组成；当前仅展示旧单次任务，不伪造周期类型。
- recent_achievements 为最近有效授予，附可跳转的定义与来源；待复核不冒充有效解锁。
- `wallet=null`，表示未实现，不显示假余额 0；`avatar={enabled:false,model_asset_ref:null}`。
- 初始无业务事实时返回空集合；不得写示例记录来满足首页卡片。

## 能力与前端 Port

capabilities 新增或细化：`home,home_preferences,profile_fields`；实现前 false、通过实现后 true。`ai_chat,ai_recording,ai_profile_update,ai_reward_pricing,avatar_renderer,avatar_redemption,recurring_tasks` 在本阶段均 false。旧开发 AI 不因界面新增容器而自动启用。

Gemini 负责 `AvatarRendererPort` 类型与静态实现：mount/update/pause/dispose，事件 ready/error/interaction；输入 character_id、可空资源引用、动作 ID、减少动效。无模型、不发请求。AI Port 只保存本地待发送输入，发送禁用；不得调用原 mock 冒充真实对话。
