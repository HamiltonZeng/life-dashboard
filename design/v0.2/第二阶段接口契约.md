# 第二阶段接口冻结 · v0.2-phase2/1.0（C0）

2026-10-20。基线 e6ff267。维护者 Codex；请求权威 Schema 为 `v0.2/packages/contracts/src/phase2.ts`，错误沿用既有 envelope。本文为实现和 Gemini 对接约定，C0 提交时新端点尚未实现；实现后的能力/测试状态写阶段日志，不凭文档宣布已完成。

API `/api/v1` 与原 `CONTRACT_VERSION=0.2.0` 保持兼容，新增 `feature_contract_version="v0.2-phase2/1.0"`。新请求仅用严格 Schema，不接受未知 reward/balance/user_id 等属性。小数/积分输出字符串，integer 观测输入数字；缺失为 null。错误 400 结构、422 引用/业务、409 版本/幂等/状态；冲突 `details.current`（若有对象），不自动覆盖。

## 1. 回执与时间

所有业务写入必须 Idempotency-Key=UUID、Origin、会话；更新有 base_version。成功 `{data: <下述对象>,operation_id:UUID}`；同键同完整载荷返回同回执，异载荷 409。组合响应不保证 data 自身有 id/version，前端须验证匹配 operation_id，再按端点验证 template/instance/record 等实体；禁止把合法组合回执当 BAD_RECEIPT。

仅服务端选当前时间；无客户端 now/历史物化参数。GET 永远只读，不生成任务、不重算发币。实例快照包含 period.start/end UTC 半开边界、锁定 timezone/rule/template_version/reward policy。单次任务定义的原结构保留，新增字段并列在实例 DTO 上，不要求旧 UI 理解新 rule。

## 2. 任务

`POST /task-templates`：`{id,module_id,title,category:"main"|"daily"|"weekly"|"monthly",timezone,completion_mode:"manual"|"record_optional"|"record_required",rule,color?,due_at?}`。

- manual 的 rule 必须 null；其他模式必须有 rule。color 为 blue/green/amber/violet/rose/cyan/slate 或严格 #RRGGBB，默认 blue；due_at 仅主线允许。
- rule 判别联合：`linked_exists:{record_type_id}`、`linked_field_gte:{record_type_id,field_key,threshold}`、`count/distinct_days:{record_type_id,threshold,filters?}`、`sum:{record_type_id,field_key,unit,threshold,filters?}`，均含 kind。threshold 为正十进制字符串。
- filters 最多5个 `{field_key,operator:"eq"|"gte"|"lte",value:<基本类型或null>}`，同时满足；gte/lte 只允许数值字段及合法数值，eq 按类型比较。字段/模板必须同用户同模块；sum 单位一致。
- linked_* 只计显式链接本实例且发生在实例范围内的记录；count/distinct_days/sum 自动匹配该范围 confirmed/未删除事实，未来事实不计。distinct_days 按锁定时区去重。
- 成功 data=`{template:<Template>,instance:<Instance>}`，创建同时物化当前实例并保留回执。

`PATCH /task-templates/:id`：`{base_version,title?,timezone?,completion_mode?,rule?,color?,due_at?,effective_from?,status?:"enabled"|"archived"}`。id/module/category 不可变。变更只影响未来实例；effective_from 缺省当前实例结束，显式时间不得更早。主线仅一个实例，不允许用模板编辑静默改变该实例快照；只允许归档。归档立即停止新物化，历史保留。响应同上，template 提供 next_definition/effective_at。

`POST /task-instances/materialize`：`{template_ids?:UUID[]}`，最多50个；省略为本人启用模板集合。data=`{instances:Instance[],reused:boolean[]}`，逐项对应；并发/重启/重放不重复。只物化当前周期，长期离线不批量制造历史空实例。

`GET /task-instances` 查询：module_id/category/status/color/pinned=true|false/period_start/limit/offset，组合 AND；status 包括 ended。响应 `{data:Instance[],page:{limit,offset,total}}`，筛选后分页。`GET /task-templates` 返回 `{data:Template[]}`。

`POST /tasks/:id/complete` `{base_version}` 兼容旧路径，新实例返回 Instance；manual/record_optional 可手动完成。已完成最新版本 no-op，旧版本仍409；cancelled/skipped 不复活。`POST /tasks/:id/revoke` `{base_version,reason}` 只撤回手动完成，原因1–500字符，保留历史、修订版本和奖励冲正；证据完成须修正来源记录。逾期仍可录真实事实/完成，但奖励受资格期限控制。

Template：现有 task_templates 行 + phase2=true、definition（冻结请求）、status、next_definition|null、effective_at|null、schedule_timezone、generation_cursor、current_instance_id|null。version 单调递增。

Instance：现有 tasks 行（id/user_id/module_id/template_id/definition/status/needs_review/completed_at/completion_origin/version/created_at/updated_at）+ `category,color,template_version,period:{key,start,end,timezone},locked_rule,progress:{value,target,source_record_ids,distinct_dates},reward_summary`。旧单次实例 category=main、period=null、reward_summary.eligibility=legacy，不补发。

周期身份采用每模板单调生成边界及唯一键，时间区变更不能形成重叠区间；新时区首周期若跨旧边界则裁剪到旧实例结束。修改资料时区不改已生成实例或指标时区；模板时区未来变更显式锁快照。

## 3. 趋势

`GET /metrics/:id/trend?range=last_7_days|month|quarter|year&grain=1d...21d|1mo&precision=0..6&exclude_dates=2026-10-01,2026-10-02&variance_enabled=true|false&variance_threshold=0.5&minimum_days=5&include_all=false`。

- range 默认last_7_days；grain 缺省分别1d/1d/7d/14d。合法组合：近7天1d；月1/2/3d；季3/4/5/6/7d；年7/14/21d或1mo。不合法422。
- exclude_dates 逗号拼接 ISO 日期，最多366天/4100字符，仅本次视图；其他开关默认false，阈值0..1、min>=3；include_all=true 显示全部原点但保留排除标记和解释。
- 日值沿指标aggregation在当地自然日计算，不累计到当天；latest不前填。先对整个范围一次算方差贡献，再按起点锚定分桶有效日等权平均，Decimal，最终 ROUND_HALF_UP（负数半值远离零）。未来日期不补零；当天未记录=null。
- 输出 `{metric_id,metric_version,range,grain,precision,timezone,start_date,end_date,aggregation,unit,daily_values:[{date,value,display_value,source_record_ids,excluded,exclusion_reasons:[manual|variance]}],buckets:[{start_date,end_date,value,display_value,valid_days,expected_days,incomplete,source_record_ids,excluded_dates}],coverage:{valid_days,expected_days,included_days},exclusions:{manual_dates,automatic_dates,applied_dates,fallback_reason:null|insufficient_samples|zero_variance|too_few_remaining},view_filter,calculation_version:1}`。
- buckets.end_date 为包含的已发生最后一天；expected_days 是桶内已发生日期数，不完整末桶 incomplete=true；monthly grain 按自然月。value 未舍入，display_value 保留 precision 位字符串。新旧业务计算不读筛选结果。

## 4. 系列与里程碑

`POST /achievement-series` `{id,module_id,name,record_type_id,aggregation:"count"|"distinct_days"|"sum",field_key:null|string,unit,timezone,filters?,history_policy?:include_existing|from_activation,milestones:[{id,threshold,label?}]}`，1–20个。sum 要兼容数值字段/单位；其他 field_key=null。阈值正数、规范化后不可重复、服务端升序。成功为 series 定义（id/version等），GET 展示进度/授予。

`GET /achievement-series` 查询 module_id/id/state(unlocked/needs_review/unstarted)/limit/offset，`{data:[SeriesView],page}`。SeriesView 为 series 行 + `progress:{value,source_record_ids,distinct_dates},milestones:[{id,threshold,label,award:null|{id,version,state,evidence,original_evidence,unlocked_at,evaluated_at}}]`。`GET /achievement-summary` 返回 `{effective_awards_count,achieved_series_count,needs_review_count,legacy_effective_awards_count}`；有效总数包含旧有效授予，达成系列数仅新系列。旧 per_period 历史原样保留。

系列累计all_time，唯一性=user/series/milestone/period_key=all_time，与规则版本无关；不推出新版周期×多门槛编辑。删除证据转 needs_review，恢复相同 award ID；不发成就额外代币。

## 5. 奖励与钱包

冻结开发默认规则 `reward-policy-v1`：main=100/月1，daily=10/日3，weekly=50/周3，monthly=200/月2；周期结束后7天（截止点含）允许首次获得资格。规则由服务端版本化，普通请求不能修改金额/余额。

用户奖励日历时区在首次新模板建立时从users锁定，之后不随资料/模板时区来回切换。周期实例的额度周期以物化当时服务端时间映射到固定奖励日历并锁定；补录用该原资格周期，不用提交当日换额度。主线以首次有效完成的奖励日历自然月确定。新模板在同一真实日/周/月不能因选择其他时区刷新额度。资格一旦 eligible/denied 均保留；撤回不释放名额，恢复用原资格。

reward_summary=`{policy_version:null|string,candidate_amount:<整数串>,net_amount:<整数串>,eligibility:pending|eligible|quota_full|expired|legacy,quota_period:null|string,reversed:boolean}`。已发资格的恢复不受首次补录期限限制；超期首次完成照常统计但资格 expired。账本按任务资格 append-only，grant/reversal/reinstatement 关联原发放和前次流水；重复重算不写重复流水。

`GET /wallet` data=`{id:<user>,version,balance,effective_earned,currency:"token",policy_version,quota_timezone}`，balance为净账本，effective_earned同当前有效发放净额（本版无消费），恢复不是新收益。无钱包写 API。

`GET /wallet/ledger?task_id=&limit=&offset=` 响应 `{data:[{id,user_id,task_id,qualification_id,ordinal,kind,amount,policy_version,root_entry_id,previous_entry_id,reason,created_at}],page}`。amount带符号整数串，授予只一次、冲正只抵销当前有效奖励。旧v0.1任务不创建新资格或补发。

## 6. 资料/观测/派生

`GET/PATCH /profile` 保留原字段。field_upserts 判别联合：profile 原结构；observation 只支持integer/decimal、value只能null（或不传），binding=`{record_type_id,field_key}`；derived 固定decimal、value只能null，binding=`{metric_id}`。绑定同用户同模块同类型/单位；不能将传入value直接当观测入库。GET observation/derived 的 value 由来源计算，并附 binding/source_ref（观测最新合法来源 `{record_id,version,occurred_at,record_type_id}`；派生提供 metric_id/source_record_ids），无来源=null。

`POST /profile/observations` `{id:<新来源record UUID>,field_id,occurred_at,timezone,value,source_record_id?,source_base_version?,context_values?:{业务字段:基本值}}`。默认新增来源记录；纠错必须同时提供 source_record_id/source_base_version，并保留该记录其他字段/关联；value按绑定类型校验。context_values 用于模板其他必需字段，不能覆盖本观测字段。拒绝未来发生时间，不猜字段或模板。成功 `{record:<来源record>,profile:<投影>,impact:{cursor,changes:[{entity_type,entity_id,version}]}}`，同事务统一重算/回执。profile和observations分开保存，无组合半成功承诺。
