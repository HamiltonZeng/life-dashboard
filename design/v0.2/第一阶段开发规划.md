# 应用 v0.2 第一阶段：主页与个人资料基础

日期：2026-10-19。状态：环境准备及任务分配完成后执行的开发计划，不代表业务功能已经完成。

## 1. 本阶段范围

依据 [应用 v0.2 PRD](../人生面板_应用v0.2需求文档_PRD.md)。第一阶段只交付：

1. 先修 v0.1 两项遗留边界：合法业务字段名误拦截、配置创建的未知结果恢复。
2. 标准主页、主页极简模式、已有数值/任务/成就展示及来源跳转。
3. 个人信息基础页：昵称、简介、时区、四模块与自定义模块的资料字段、未保存提醒与版本冲突。
4. 首页偏好和个人资料的后端持久化、导出/恢复兼容。
5. AI 对话/AI 记录禁用容器与草稿、3D 静态占位和渲染接口类型；能力真实声明为未开放。
6. 新功能的独立测试与原有手动闭环回归。

本阶段不做周期任务调度、趋势算法、里程碑成就、代币发放账本、观测修改联动、真实 AI、3D 渲染或模型兑换。它们进入后续阶段，不能在第一阶段先显示虚构钱包余额或假趋势。

第一阶段用真实的现有单次任务/数值/授予填充首页；主线/每日/周常/月常分类及新系列成就将在相应数据能力完成后再接入。个人资料此阶段只编辑资料/配置，不直接修订观测或累计统计。

## 2. 当前目录与运行基线

- `v0.1/` 保留 README、发布说明、docs 及环境归档说明；原应用、依赖、缓存、私有配置和物理数据库已移动到 `v0.2/`。
- `v0.2/` 业务源码仍是 v0.1 验收基线，尚无本阶段新功能。仅为环境切换调整 Compose 项目名，并新增离线启动/隔离辅助脚本与文档。
- 主集成环境：`life-dashboard-v0-2`，入口 `http://localhost:18080`。它保留用户数据，不向开发任务提供清库权限。
- v0.1 原容器停止并保留；一致性数据库备份与迁移指纹在 `v0.2/.runtime/migration-v02/`，不入 Git。
- 不重新安装依赖、不改依赖版本。三个 agent 容器只读挂载主版本现有 node_modules 与 Corepack 缓存；各自源码、数据库、密钥、临时文件和产物独立。

## 4. 并行启动方式

独立工作树位于以下目录，均从同一个准备基线建立。实际基线提交通过各工作树 `git log -1` 查看；正式交付需记录自身提交和共同起点，不拿旧 `c91eee9` 作为迁移后路径基线。

| Agent | 开发目录 | 独立项目与入口 |
| --- | --- | --- |
| Codex | `/Users/zhk/life_dashboard/v0.2/.runtime/worktrees/codex/v0.2` | `life-dashboard-v0-2-codex` · `http://localhost:18181` |
| Gemini | `/Users/zhk/life_dashboard/v0.2/.runtime/worktrees/gemini/v0.2` | `life-dashboard-v0-2-gemini` · `http://localhost:18182` |
| DeepSeek | `/Users/zhk/life_dashboard/v0.2/.runtime/worktrees/deepseek/v0.2` | `life-dashboard-v0-2-deepseek` · `http://localhost:18183` |

**不要在 agent 工作树里裸用 `docker compose` 启动服务**，否则会使用主项目名和 18080。统一从主版本目录调用：

```sh
cd /Users/zhk/life_dashboard/v0.2
sh scripts/agents/start.sh codex
sh scripts/agents/start.sh gemini
sh scripts/agents/start.sh deepseek
```

这些命令分别启动三套隔离运行环境；按实际需要启动自己的即可。不会重新安装依赖；没有本地镜像或依赖时会失败并交给集成负责人处理，不自动联网安装。初始库只含默认配置，没有用户真实记录。

类型检查示例：

```sh
sh scripts/agents/compose.sh gemini run --rm --no-deps --pull never tools node_modules/.bin/tsc --noEmit
```

停止单个环境：

```sh
sh scripts/agents/compose.sh gemini stop
```

不能在并行环境中运行旧的根 `scripts/verify-all.sh` 或 `scripts/release/verify-mvp.sh`，它们没有绑定 agent 隔离参数。需要集成测试时使用 wrapper 的 test profile；新增阶段浏览器测试也必须接专用隔离库，不在 18080 主环境写夹具。

## 5. 契约先行与并行规则

本轮交付 [第一阶段接口契约](第一阶段接口契约.md)，作为三方共同输入。它定义本阶段 API/DTO/错误边界，不代表端点已实现。Gemini 可直接根据它使用明确标注的测试夹具开发视图；DeepSeek 可立即编写预期测试；Codex 同时实现服务端，无需三方等待同一个源文件。

契约变更只能由 Codex 在协调后更新文档及公共 Schema；不得让三个工作树各自创造不同字段。夹具只用于测试/开发，不写用户数据库，也不能将 mock 页面作为最终集成通过证据。

合并顺序：Codex 契约/API → Gemini UI → DeepSeek 验收用例。DeepSeek 最终在集成后的新提交或快进更新后的专用工作树验收；有冲突由集成负责人处理，不用覆盖目录的方式“合并”。

任何 agent 不得自行安装包、改 lockfile、清主库、调用真实模型、租服务器或推送远端。新增依赖确有必要时由 Codex 单独审查，本阶段默认零新增依赖。
