## 5. 共同业务约束

### 5.1 周期任务

`main / daily / weekly / monthly`；展示为主线任务/每日委托/周常委托/月常委托。周一开始，按自然月，无“季度委托”。实例锁定模板版本、完成规则、时区、UTC 半开周期边界、奖励策略引用。

采用按需物化：创建模板时在同事务产生当前实例；应用初始化/进入任务页显式请求物化当前周期，服务端唯一约束兜底。GET 首页保持只读。首次启用不补建大量历史空实例；重启、并发物化只能产生一个当前实例。

时区/模板变更只对未来生效，已有实例保留快照。时区变更的生效点不得早于当前实例结束；周期身份、生成游标和奖励额度不能因时区来回切换重置。Codex 必须为跨日线/DST/新建模板后额度复用写对抗用例，不能仅把 timezone 加进唯一键。

验收规则区分单条显式关联与周期内自动匹配（count/distinct_days/sum）；周期聚合按实例锁定模块、模板、发生时间和字段过滤，confirmed 且未删除的事实各计一次。取消/跳过不被重算复活；周期结束未完成明确显示 ended。手动撤回必须有版本、原因和审计。

颜色仅允许色板或严格 `#RRGGBB`，不接受 CSS/HTML。固定周期任务引用模板，首页解析当前实例；旧单次任务引用保持兼容。

### 5.2 趋势

近七天 1 天；本月 1/2/3 天；本季度 3–7 天；本年 7/14/21 天或自然月。范围到用户当地今日，桶以范围起点锚定，最后不足桶标 incomplete。

先按指标计算每天值，再对有效日等权平均。累计指标取当日增量/聚合，latest 不向缺失日填充。null 不等于 0；返回有效天数、应有天数、未舍入值、显示值和来源。Decimal 计算，最终 ROUND_HALF_UP，默认 0 位，不用二进制浮点逐层舍入。

方差贡献基于所选全范围有效原始日值一次计算，默认阈值 0.5、最少 5 日（可调但不低于 3）；零方差/不足样本不剔除，剩余少于 2 点回退。手工排除与自动筛选均仅作用视图，切粒度不改排除集合；提供原始全点切换。首页复用同一趋势查询，补录/编辑/删除后两处刷新。

### 5.3 里程碑

系列内阈值排序且不可重复；跑步天数必须 distinct local dates。达到 10 天的 1/3/10 系列产生三条有效授予；跨级解锁不漏级。唯一性覆盖用户/系列/里程碑/业务周期，不因规则版本变化重复领取。证据失效保留原 award 转 needs_review；恢复后恢复同一 award ID。

有效授予总数、达成系列数、待复核数分别计算。兼容旧单阈值及 per_period 历史，不将旧授予复制成多条。

### 5.4 代币

初始建议沿用 PRD：主线100/月1、每日10/日3、周常50/周3、月常200/月2；补录奖励窗口周期结束后7天。这些仍是**拟定开发默认值，未获用户金额确认**；S0 统一冻结为有版本的服务端规则，若用户无新调整就采用该建议，不新增个人可改奖励设置。

实例建立时锁策略与候选金额；首次有效完成按确认顺序占资格，额度满仍可完成。资格保留，撤回不释放供另一任务反复领取；恢复使用原资格。补录按发生周期结算，不按提交当日换额度，逾期事实仍正常统计。

任务状态、资格、账本在同事务/用户锁下写入；唯一键与回执同时防重。账本 append-only，grant/reversal/reinstatement 引用完整；冲正只能抵销尚有效的对应发放，不能凭重复冲正产生负余额。余额是账本净额，累计有效获得不把恢复流水重复计收入。不迁移补发 v0.1 历史完成任务。

### 5.5 个人信息与 AI

profile 只改资料；observation 保存新增带时间的合法来源记录，纠错时显式选择记录和 base_version；derived 只读并跳来源。绑定校验同用户/模块/模板/数值类型/单位，无法映射只能保存资料，不能伪造事实。多字段资料与观测若一次提交，需原子性；也可 UI 分开保存并逐项明确结果，禁止整体失败时留下半组事实。

AI 仅留上下文/候选/预览/应用端口与 Schema，普通候选禁止余额、奖励、完成/解锁等权威字段；奖励报价是独立服务端内部协议。保留旧 module_blueprint 1.0。mvp 发布能力全为 false，缺省 provider=disabled。记录内自然语言当数据，不成为权限或代码指令。

## 6. S0 应冻结的接口草案

下列为下一阶段设计输入，**目前尚未实现**。Codex 在写业务前将精确请求/响应和错误 Schema 落入公共契约并通知 Gemini；不能双方各发明一份接口。本版沿用 `/api/v1`，增量扩展，旧 API 继续可用。

| API 草案 | 关键输入/输出 |
| --- | --- |
| `POST /task-templates`、`PATCH /task-templates/:id` | id/module_id、category、timezone、completion_mode、rule、color；更新含 base_version/effective_from，响应模板和当前实例引用 |
| `POST /task-instances/materialize` | 模板引用或当前启用集合；服务端取当前时间；响应实例引用与 reused 标记；禁止客户端指定任意历史奖励周期 |
| `GET /task-instances` | 类别/模块/状态/颜色/固定/周期筛选及分页；实例含锁定规则、period、reward_summary |
| `POST /tasks/:id/complete`、新增 `POST /tasks/:id/revoke` | 兼容旧完成路径；base_version；撤回含 reason；均返回实例和奖励状态摘要 |
| `GET /metrics/:id/trend` | range=last_7_days/month/quarter/year；grain=1d…21d/1mo 合法组合；precision；view_filter；返回 daily_values/buckets/coverage/exclusions/source_refs |
| `POST /achievement-series`、`GET /achievement-series`、`GET /achievement-summary` | 系列定义、计量口径/阈值、进度、全部 milestones/awards、effective_awards_count/achieved_series_count/needs_review_count |
| `GET /wallet`、`GET /wallet/ledger` | balance、effective_earned、policy版本；分页账本含任务/原流水/原因，无钱包写入 API |
| `GET/PATCH /profile` 增量扩展 | 保留 profile 字段；增加 observation/derived 绑定与 source_ref，不接受直接写累计结果 |
| `POST /profile/observations` | field_id、occurred_at/timezone、value、source_record_id?、source_base_version?；响应来源记录、投影版本/影响摘要；由统一事实写服务执行 |
| `GET/PATCH /home-preferences` 增量扩展 | 保留旧 pinned_task_ids；新增类型化 task_pins（template/instance）、pinned_trends（metric/range/grain/filter/order）并定义去重/迁移优先级 |
| `GET /home` 增量扩展 | 当前周期任务、真实趋势、里程碑细节、钱包；保留第一阶段字段兼容和失效 pin warnings |
| AI 端口草案 | context/proposal/preview/apply 的契约类型、上下文白名单；运行请求返回 FEATURE_DISABLED，无真实写入 |

所有业务写入有 Idempotency-Key、冻结载荷、操作回执与版本；冲突返回 409/current，引用/类型非法明确 400/422，能力未开 FEATURE_DISABLED。新增聚合响应不能假设都具有单实体 id/version：Gemini 必须为新端点扩展回执判定，不能沿用当前通用校验后把成功误判成 BAD_RECEIPT。

趋势筛选不塞进 GET 请求体；S0 明确序列化方式、长度上限和隐私最小化。返回金额/精确指标为十进制字符串、时间为带时区 ISO、缺失为 null。rule 用带 kind 的判别联合，禁止任意 JSON patch。后端 schema 是契约来源，前端镜像类型只映射不另定规则。

AI 能力至少分别列 ai_chat/task_generation/metric_analysis/achievement_generation/recording/profile_update/reward_pricing、avatar_renderer/redemption；全部 false。recurring_tasks/trends/achievement_milestones/token_wallet/profile_observations 仅在其真实实现并验收后为 true。
