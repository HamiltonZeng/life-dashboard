## G1：可靠提交

1. **先落盘再发送**：发送前保存完整 pending envelope，含 operation_id、record ID、载荷、方法/目标、创建或编辑基线及状态；刷新后可恢复未确认操作。
2. **未知结果保留**：网络无回执不能代表失败。用户修改草稿时保留旧 pending，工作草稿与冻结载荷分开；先按旧键/旧载荷确认结果，再选择更新同一记录。不得默默分配新 record ID 或丢弃旧操作。
3. **精确载荷**：一致性判断覆盖 occurred_at、timezone 等业务字段；重放永远用冻结值。修订旧 S1-03 的错误期望，新增“旧提交已成功且回执丢失→用户改为新内容”回归。
4. **真实持久化状态**：存储读写返回可判断结果。配额满、被禁用、JSON 损坏等明确提示；内存回退只能称当前页面保留，不能称“已保存本机”。提供重试/复制输入，不静默丢失。
5. **编辑基线**：打开编辑时固定 base_version，普通刷新不能把旧输入自动套到最新版本；409 保留本地输入并显示服务器差异，只有用户明确采用新基线后才可重新提交。
6. **确认回执校验**：保留写接口收到预期响应后才清草稿/pending；2xx 但空/损坏 JSON 或缺必要字段，应进入待确认。接口失败与后续 bootstrap 刷新失败分开处理，已确认的写入不能被刷新失败改判为新写失败。
7. **基础防重与体验**：提交中锁双击，Toast 与局部重绘不吞输入。丢弃草稿不等于撤销已发送请求，不能顺带删除未确认凭据。

不要扩展到 PWA、后台 outbox 或多设备合并。当前单用户本机 MVP 可沿用 localStorage；存储可靠性必须真实告知。
