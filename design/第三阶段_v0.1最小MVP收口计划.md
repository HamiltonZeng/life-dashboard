## 2. 冻结后的 MVP 定义

**一个在本机 Docker 运行的单用户人生记录网站：手动配置任务、记录实际行为、查看可追溯数值和成就，能保留草稿、处理重复提交与冲突，并导出/恢复已确认数据。**

v0.1 的发布承诺限于本机浏览器使用。保留手机宽度适配，但可信手机入口、后台离线与跨设备同步进入后续版本。记录保存到本机 PostgreSQL；浏览器草稿只是当前浏览器的数据，不宣称能跨设备恢复。

沿用原生 TypeScript、Fastify、PostgreSQL、Docker、现有构建和编号 SQL 迁移，不换框架、不新增数据库、不建设队列平台。本阶段原则上无需新迁移；确有阻断问题才由 Codex 统一评审迁移。

## 4. 必须先补齐的记录可靠性边界

下列为本轮源码核对发现的风险，需要先写反例验证，再修复。尚未进行新的故障注入，不把它们列为全部已复现的缺陷。

| 编号 | 源码现状 | 第三阶段要求 |
| --- | --- | --- |
| M1 | `main.ts` 在捕获未知网络错误后才保存 pending envelope | 请求发出前持久化 operation_id、实体 ID、完整冻结载荷；请求中刷新/关闭后仍可重放 |
| M2 | `forms.ts/storage.ts` 在未知结果后字段变化时删除旧 pending 并生成新操作 | 保留未确认操作；先重放确认旧结果，再对同一记录发显式新编辑，不能把一次记录变成两条 |
| M3 | `writeJson` 吞掉存储异常，内存回退可能仍显示“已保存本机” | 返回持久化结果；失败明确提示未保存，保留输入并支持重试/复制；不能假报刷新可恢复 |
| M4 | `computePayloadSignature` 未覆盖 occurred_at/timezone | 时间与时区变更参与载荷一致性判断；冻结载荷重试仍逐项相同 |
| M5 | 记录提取可能使用最新 bootstrap 的 version，冲突处理自动更新基线 | 编辑基线保持为用户开始编辑时的版本；刷新不能悄悄跳过冲突，重新提交须明确选择新基线 |
| M6 | API 客户端对成功响应 JSON 解析失败回退空对象 | 对保留的写接口校验确认响应；2xx 但回执损坏仍保留待确认操作，不能清除草稿假报成功 |

M1–M6 是同一个可靠提交闭环的组成部分。完成它们即可，不扩展成多设备同步系统。现有前端 S1-03 把“修改后清理旧 pending”当作成功条件，需要随本阶段语义一起修订，不靠保留错误测试维持绿色。

推荐最小实现仍使用当前浏览器存储：一个持久化操作包作为重试依据，另存可编辑草稿。无需为了这个闭环引入完整 IndexedDB outbox。存储不可用时保留输入，可靠提交路径不得绕过持久化后仍承诺刷新可恢复。

## 5. 发布模式与 API 冻结约定

由 Codex 先实现并冻结一个服务端配置：`APP_PROFILE=mvp|development`，默认 `mvp`；未知值拒绝启动。它只用于本次发布收口，不建设通用插件或权限平台。

| 行为 | mvp | development |
| --- | --- | --- |
| 核心手动流程 | 开启 | 开启 |
| AI 蓝图能力 | 关闭 | 保留现有实现，默认 mock |
| AI 写操作 | 返回统一 `409 FEATURE_DISABLED`，不建 job/调用模型 | 按既有校验和时限执行 |
| 能力响应 | `ai_generation=false`、`ai_preview=false`、`cloud_ai=false` | 按实际 provider 配置响应 |
| 同步/周期/专业账本 | false | 仍按当前未实现能力返回 false |

AI 路由需服务端防守，不能只藏按钮。MVP 不因遗留模型配置错误而无法启动；禁用时不执行外部调用，也不让模型初始化阻断核心流程。AI 状态读取入口在 MVP 返回诚实禁用状态或统一禁用错误，由 Codex 在第一批契约说明中固定。

前端仅根据服务端 capability 显示功能，不能自己另造一个互相矛盾的开关。旧 AI 测试显式使用 development + mock，继续保留；新增 MVP 测试确认禁用有效。请求契约若需变更，由 Codex 统一评估版本，其他 agent 不自行改版本或 lockfile。

首页继续空白；移除记录面板 AI 复盘标签、各面板 AI 生成按钮和设置 AI 子页。遇到旧子页状态，回到所属面板的默认可用子页，不崩溃、不出现空洞内容。账户页的内部 capability/游标信息可收进“版本与能力”说明，不包装为同步功能。

| 编号 | 必须通过的场景 |
| --- | --- |
| A01 | 全新隔离环境安装/迁移/启动，配置与数据目录正确；种子无虚构事实 |
| A02 | 登录/退出、未登录 401、跨 Origin 拒绝；发布入口维持本机绑定 |
| A03 | 空白首页与五面板正常；无 AI/报告/同步等延期功能入口 |
| A04 | 自定义模块、通用模板、任务、数值、成就可通过界面手动建立 |
| A05 | 一条 5 分钟记录不足 10 分钟任务；编辑为 10 后达标；一条记录绑定多任务不重复计数 |
| A06 | null 与 0 分开；证据修改/删除后任务和授予按规则复核，历史保留 |
| A07 | 输入草稿刷新恢复；Toast/刷新快照不吞未保存输入 |
| A08 | 请求已发出、服务端已提交、响应被丢弃时刷新，重放仅有一条事实与原回执 |
| A09 | 未知结果后修改输入：旧操作保留；确认旧结果后显式更新同一记录，没有双记 |
| A10 | 修改时间/时区不会静默重放旧载荷；成功响应损坏不假报确认 |
| A11 | 存储配额/权限失败时明确未持久化，刷新前可见失败；无“已保存本机”假提示 |
| A12 | 双页面版本冲突保留输入；普通刷新不自动获得覆盖权限；选择后重新提交基线明确 |
| A13 | 数据导出成功；空隔离库恢复后事实、墓碑、修订、回执一致，重新登录可读；篡改/非空/迁移不符拒绝 |
| A14 | MVP 直接调用 AI 写 API 被拒绝，无 job/批次/外部调用；development + mock 的原 AI 回归仍通过 |
| A15 | 360px 真实浏览器视口：能打开记录、输入、提交，保存按钮不被导航遮挡；真机未测则明确记录 |
| A16 | 重启应用后数据仍可读取；停止/启动说明、数据目录和备份限制与实际一致 |

除后端/存储层测试外，A04–A12 和 A15 至少有实际浏览器关键流程覆盖。可采用测试请求控制/受控响应丢弃，但正常 CRUD 必须接隔离真实 API 与 PostgreSQL；不能整套 mock HTTP 后称为集成成功。

正式发布验证命令为第三阶段待实现的 `sh scripts/release/verify-mvp.sh`。它应编排 Docker 工具链、隔离数据库、Web/构建/契约/审计、真实浏览器关键用例和恢复演练。当前 `verify-all.sh` 仍有效，但不能代替上述新增验收。

发布命令不应在缺浏览器时以 SKIP 当 PASS。可明确依赖宿主浏览器或由 Codex 接入测试专用容器，记录实际执行环境；不声称已有 CI。所有报告保存到 `v0.1/.runtime/test-artifacts/stage3-<agent>/` 或 `stage3-final/`。测试事实与浏览器档案不进入主开发数据。
