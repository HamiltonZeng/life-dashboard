# v0.4 Harness 开发规划

v0.4 完善自然语言操作的执行可靠性。目标是让用户用一句话创建任务、录入事实或生成报告，系统能区分何时保存、何时确认、何时追问。v0.5 负责整体前端改版。v0.4 可以更新承载澄清、校验和回执所需的文案与交互。

当前 v0.3 已有 DeepSeek 网关、事务预检、模型用量预算、记录来源、确认和补偿撤销。v0.3 修复补齐三类任务规则冲突的有限纠错，本版继续处理跨动作的一致性，并使用实际模型效果决定是否更换适配器。[故障及迁移调研](../v0.3/Harness收口与迁移评估_2026-11-27.md)

| 阶段 | 实施范围 | 交付与验收 |
| --- | --- | --- |
| 1. 统一任务与记录的输出契约 | 建立任务、记录、报告各自的简明模型输入。给手动、时长、次数、跨日、同名模板加中文例子。确定性校验输出阶段、动作路径和原因码，诊断只保存白名单字段。将模型修正反馈与用户实际回答分离 | 原任务失败能定位到具体动作和字段。明确需求可在一个模型重试内形成可预览候选，缺目标值或含义不明确时提示具体问题。事实数字、日期精度及授权范围由服务端复核 |
| 2. 统一失败分流与权威写入 | 共享取消、租约与预算守卫，区分候选错误、需要澄清、权限变化和系统错误。规划、记录和报告的查询只取已授权内容。写入前复核版本、来源、授权和幂等标识。前端能说明失败原因、打开确认及查看保存回执 | 背景作业排队、服务器重启和重复提交可回归。撤权、过期、取消、超额或用户改变意图触发相应终态。失败方案零业务部分写入、零额外发币。报告继续从 SQL 事实快照取数 |
| 3. 用真实 DeepSeek 验收 | 固定中文合成题集与配置。先跑隔离测试，再用受控额度和仅含合成数据的真实调用，对比 v0.3 与 v0.4。记录模型、提示版本、首轮有效率、两次内有效率、澄清正确率、输入输出与缓存 token、p50/p95 延迟 | 先接受一套建议至少 20 条的规划、记录、纠错和报告场景作为基准。报告原始计数和每项失败原因，成功必须通过业务校验与回执验证。权限、账本和数据安全约束在所有样例中保持有效 |
| 4. SDK 可选实验与交接 | 用同一套合成数据评估 Vercel AI SDK 的 DeepSeek 适配器。只有确实需要通用会话或插件编排时，再评估官方 DSH 的隔离最小配置。将稳定的澄清、预览、成功、失败状态及数据来源接口交给 v0.5 | 对照实现用同一预算、超时与数据范围。除非质量或多供应商维护有可测改进，继续保留现有适配器。数据库与前端无需切换即可回退。v0.5 可根据稳定状态完成布局与交互 |

实施顺序从任务验收和事实录入开始，再接资料、报告和代币报价。新增模型调用统一计量，保留既有用户日额度、每用途上限和父意图总预算。示例和测试数据继续与个人数据库隔离。

本阶段不扩大 AI 可执行操作。报告日期、记录事实、模块权限和账本由既有服务管理。前端重排、移动导航及视觉规范见 [v0.5 前端方案](../v0.5/前端升级方案.md)。
