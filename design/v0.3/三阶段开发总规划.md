# v0.3 三阶段开发总规划

日期：2026-10-20；2026-10-21按用户新要求调整阶段边界。状态：第一阶段已收口并复核通过，第二阶段待实施。开发、测试、集成及日志均由 **Codex** 负责，不分派给 Gemini 或 DeepSeek 开发 agent；DeepSeek 仅作为应用运行时的模型供应商。

## 1. 总体目标与拆分

沿用[需求与交互设计](需求与交互设计.md)、[AI接口与数据契约](AI接口与数据契约.md)和[技术实施与验收规划](技术实施与验收规划.md)。本规划细化实施顺序，不削减完整 v0.3 的必交范围。

本次用户明确要求第二阶段完成主要功能代码，供第三阶段API接入测试，因此原第三阶段的报告调度、长期统计/摘要检索及相应页面前移第二阶段；旧阶段安排以本次更新为准。

| 阶段 | 交付目标 | 用户可实际使用 | 阶段出口 |
| --- | --- | --- | --- |
| 第一阶段：AI基础与目标规划 | 独立开发环境、DeepSeek网关、持久会话/作业、受限动作编译与原子应用、主页和新建任务入口 | 说出目标，生成有关联的长短期任务、记录模板、指标和系列成就；可追问、预览、查询结果和撤销 | 目标规划闭环通过；手动录入能驱动新计划；错误、幂等、事务、备份和旧功能回归通过 |
| 第二阶段：主要功能全部落地 | 自然语言记录/纠错、资料/未来计划/新模块、三类报告及日程调度、独立报价、长期数据与面板简化 | 在受保护合成环境完整跑通规划→记录/纠错→联动→报告→日程→恢复，交付真实API脚本 | 本版主要前后端/数据库/调度代码与离线验收完成，可进入真实供应商联调 |
| 第三阶段：真实API与整版验收 | DeepSeek连接/模型兼容、真实语言效果/报告分析/报价、费用/错误/故障、跨工作流/浏览器/手机/升级验证与必要修复 | 核对真实模型、应用API及全链路效果 | 完整v0.3验收、最终日志、运行/数据升级/回滚说明与发布候选 |

第一、二阶段各自包含测试，不将基础正确性留到第三阶段。第三阶段允许联调修复和供应商兼容调整，不再承担报告自动化等主功能的从零实现。

| 能力 | 第一阶段 | 第二阶段 | 第三阶段 |

| 有效期、每日适用星期、到期停生成 | 实现 | 验证计划调整边界 | 时间边界回归 |
| 自然语言记录、历史纠错、资料更新、营养估算 | 保留接口，能力关闭 | 实现 | 全链路回归 |
| 日报/周报/月报 | 保留接口，能力关闭 | 三类按需、快照/修订、独立日程、可靠调度/关闭/补生成 | 真实分析效果、API/故障与整版验证 |

| 各面板一句话入口 | 首页与新建任务 | 记录/数值/成就/资料/报告入口、手机视口/键盘/错误恢复实现 | 真实模型、浏览器/手机与整体体验验证 |
| 备份恢复与迁移 | 当阶段新增数据当阶段纳入 | 扩展记录/报价/报告 | 完整升级恢复演练 |
| 长期数据 | 冻结上下文、会话分页、目标/计划版本 | SQL事实快照/报告摘要、可重建日统计、检索/失效；不装向量库 | 长历史实际效果、权限/统计准确性及性能验证 |

本地存储与Docker开发不变；VPS部署、跨设备同步、原生APP、3D模型/兑换和v0.4视觉重做不在本版本范围。手机浏览器适配在本版验证，跨设备同步另行实施。

依赖顺序为：统一契约与领域事务口 → 会话/作业 → 规划应用 → 记录与报告事实 → 自动调度与整版验收。报告建议不会自动执行；明确采纳后再走受限动作链路。

## 3. Codex的工作方式

1. 全部任务由同一Codex实施线维护；先完成一项并验证，再进入依赖项，不同时启动会修改相同服务/迁移的多个任务。
2. 第一阶段见[第一阶段开发规划](第一阶段开发规划.md)及[收口复核](../../v0.3/docs/phase1/收口复核_2026-10-21.md)；下一步执行[第二阶段开发规划](第二阶段开发规划.md)、[接口交接](第二阶段接口与集成交接.md)和[Codex执行单](tasks/第二阶段_Codex执行单.md)。第三阶段按实际冻结候选运行真实联调，不提前编造结果。
3. 公共契约、迁移编号、应用事务、前端Controller由Codex统一维护；不为“前端/后端/数据库分工”复制三套协议或独立数据库模型。
4. 每项任务日志记录：代码范围、迁移/契约变化、实际验证命令、结果、遗留问题和下一项。完成一次共同接口导出，复用同一组测试夹具。
5. 先用离线合成数据和可控模型stub验证。真实DeepSeek测试单独启用并限额；没有密钥时继续完成独立工作，但真实联调必须标记未验证。

## 5. 完整版本的完成条件

完整v0.3必须覆盖产品验收项V03-01～V03-17。仅第一阶段通过不能称为“v0.3已完成”。阶段内未开放能力通过配置如实返回false，不用占位按钮、mock响应或旧development总开关冒充实现。

每阶段应交付阶段日志、测试矩阵及风险/遗留清单。最终交付另含版本介绍、运行/密钥配置说明、备份恢复/回滚说明、已验证的模型版本与真实API结果；手机实机未测、外部计费未知等实际限制单列。
