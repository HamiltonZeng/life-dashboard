# 人生面板 v0.3：AI 接入与交互简化

日期：2026-10-20。状态：待开发的完整设计稿；用户本轮确认“先交付完整设计与接口文档”。本文不代表功能已上线，不修改18080、不调用付费模型。

## 1. 版本定位

v0.3把“用户操作一组配置表单”变成“用户说一句话，应用完成规划与记录”。首页聊天是统一入口；任务、记录、数值、成就和资料仍是可信数据视图。AI负责理解、提出结构化操作和解释；服务端负责事实、统计、达标、发币、权限、版本和事务。

继承已升级的v0.2主环境，基线6ccc4a1，版本0.2.0-rc.1。v0.2支持主页/极简、四类任务、趋势、系列成就、代币、资料/观测和可靠写入；AI容器及动作协议仍禁用。v0.3需开发完整运行链路，不能只把发送按钮启用。

| --- | --- |

## 2. 一句话操作的产品原则

1. **普通入口只留需求输入框和提交。** 手机输入框视觉上从一行开始，可自动增高；不要求用户填写模块ID、统计函数、阈值、时区、绑定字段或JSON。
2. **AI隐藏配置复杂度，保留有意义的说明。** “每天20分钟”“本月结束”“按不同日期计数”等影响行为的内容用自然语句呈现；数据库类型、规则版本、贡献阈值等默认折叠。
3. **明确指令自动完成合法新增。** “帮我安排”“新建”“记一下”不再逐个确认十张表单；成功后显示短回执、查看/调整/撤销入口。开关允许用户改为“先预览”。
4. **缺事实才追问。** 不用默认值补造已发生时长、距离、收入、体重或任务完成。目标阈值可以建议，必须标为计划；真实记录不能猜。
5. **高影响修改只确认一次差异。** 历史记录纠错/删除、批量覆盖既有计划、导入历史解锁、启用收费定时任务展示一张摘要确认卡，不让用户回到复杂表单。
6. **失败明确可恢复。** “已识别”“方案已准备”“等待确认”“已保存”分开；未知网络结果沿原键确认，不重复建任务、事实或报告。
7. **AI不可用时仍能工作。** 一句话草稿保留，显示重试及“高级手动录入”；原手动能力保留，默认不占首屏。

自动执行策略由服务端和用户设置决定，模型不能在输出中自称已获权限。记录正文、历史聊天、报告内容和检索文档不是新的执行授权。

## 3. 首页聊天与计划工作流

首页保留v0.2标准/极简模式；同一个会话可识别问答、目标规划、记录、调整和报告请求。面板入口携带受限上下文，用户不必重复选择模块。

| 用户输入 | 预期行为 |
| --- | --- |
| “帮我安排未来30天每天学英语20分钟，并设置坚持成就” | 找可复用模板；创建目标、主线/每日任务、数值、不同日里程碑；不创建学习事实；反馈安排与结束时间 |
| “我每周只有一三五能练，每次半小时” | 补充可用时间约束，未来周期采用新版本；当前已锁实例保持原规则 |
| “今天跑了3公里，用了20分钟，记一下” | 解析发生日/单位/模块，写一次记录；服务端重算数值、任务、成就和必要奖励；显示结果与依据 |
| “我打算明天跑3公里” | 形成目标/任务，不作为已经跑步的事实 |
| “把昨天那次3公里改成4公里” | 定位候选来源；多条时先问选哪条；一张差异卡确认后以来源版本修订并重算 |
| “我这周学习怎么样” | 读取授权的本周统计与覆盖率，解释真实变化；不悄悄创建目标或改记录 |
| “每天早上8点给我昨天的日报” | 形成日程变更卡，清楚显示周期/时区/费用限制；一次确认后启用 |

目标规划流程：识别目标与期限/可用时间→复用模块及模板→形成依赖完整的方案→服务器检查可执行性和重复对象→自动应用允许部分或展示整组预览→返回实际创建结果。

只缺可建议的配置时，AI提出合理默认并列在摘要中，不追问内部字段。缺影响计划可行性的关键约束时，一次只问最关键问题，如“目标日期”和“每天可投入时间”；可跳过并采用明确标注的建议。涉及身体/财务的精确实际值不因规划需要自动假定。

### 目标与计划数据边界

- 目标是持久对象，保存原始意图、起止日、成功标准和约束；每次调整形成计划版本。任务、数值和成就引用所属目标/计划版本，可单独查看。
- 主线承载阶段目标；每日/周常/月常承载行动。一个目标不必机械生成全部四类，避免重复任务与奖励。
- 不把“累计完成子任务数”冒充v0.2已有的任务验收规则。首版主线可手动确认，或绑定现有可计算事实；子任务达成率作为解释性投影。未实现的验收算法必须拒绝或追问替代方案。
- v0.3新增计划有效期、每日模板适用星期和偏好时间。到期停止未来实例；偏好时间不是手机提醒。周/月仍按既有自然周期；不支持的复杂循环先说明，不把“一三五”误做每天。
- 配套成就从可验证记录计算。默认新计划从启用后计入；若要纳入旧记录并解锁历史里程碑，摘要说明后确认。成就不会被模型直接设为已解锁。
- “累计不同日期”与“连续天数”不是同一算法。首版复用累计不同日计数；用户明确要求连续N天时必须说明支持范围或追问，不能用累计算法却给出“连续达成”标题。
- 先复用相容模板/指标，创建前做语义候选查重；同名不等于同对象，重试靠稳定操作键和ID防重，不靠名称。

## 4. 执行、追问和确认矩阵

默认产品模式为“自动完成明确请求”；用户可在设置切换到“每次先预览”。以下策略是v0.3拟定默认，不是本轮对真实个人数据的操作授权。

| 行为 | 默认处理 | 应用后的反馈 |
| --- | --- | --- |
| 明确新建目标/任务/模板/指标/成就 | 低风险、小规模且无缺项时整组自动应用 | “已安排”，展示计划摘要、对象入口和撤销 |
| 明确记录已发生事实 | 信息完整、来源明确时自动写入；一次消息默认最多5条 | “已记录”，展示关键值/日期与受影响结果 |
| 只询问、假设、未来计划或讨论示例 | 回答或形成建议，不落实际记录 | “建议/计划”，不显示已完成 |
| 已有历史记录纠错/删除 | 一张差异卡确认，带版本与绑定指纹 | “已修订”，保留旧版本与影响 |
| 未来计划调整 | 明确指令、无冲突且未覆盖历史时自动采用未来版本 | 显示生效时间及当前实例不变 |
| 大批量创建、覆盖/归档旧方案、涉及历史授予 | 一次整组预览确认 | 展示旧/新对象与历史保留方式 |
| 开启或扩大收费定时报告 | 一次确认时间、频率、范围与预算约束 | 展示下次运行时间；可随时关闭 |
| 关闭定时报告 | 明确指令即关闭未来自动任务 | 说明是否仍有本次已发出的模型调用 |
| AI奖励报价 | 由独立服务端报价通道处理 | 金额只读；不能用聊天指令指定余额或奖励 |

拟定自动创建上限：一次不超过12个配置对象、4个任务模板、2个指标、1个成就系列（最多5级）；动作包硬上限20项。超限展示一张方案卡确认或拆成有标识的独立方案，不静默截断。服务端计算风险；模型confidence不能绕过确认。

同一消息的相互依赖写入作为一个事务，关键事实未齐时先追问，不能留半个计划。独立报告生成与业务写入为不同作业，回执分别说明状态。

## 5. 记录与数值自动更新

AI识别用户自述事实，并保留原消息/片段、日期解析、单位转换和字段来源。服务器使用消息接收时区和接收时间解析“今天/昨天”，冻结后不因跨午夜重试改变日期；若用户说的是不同地区日期，需要明确时区。

只说“今天”不等于声明了精确时刻。记录额外保存时间精度及解析依据；为适配旧timestamp列可使用该日稳定的归档时间，UI按日期显示，不能把归档时刻当成实际运动时刻或分钟级达标证据。相同内容的新消息也可能代表第二次真实活动：重复保护靠消息/操作ID；疑似重复可问一次，不直接合并两次活动。

自动记录链路为：`用户自述 → 结构化候选 → 字段/单位/引用/版本校验 → 统一记录写入 → 数值/资料投影 → 任务/里程碑/奖励重算 → 实际回执`。AI不直接写指标当前值、累计值、钱包或完成状态。

| 情况 | 处理 |
| --- | --- |
| “跑了3公里，20分钟” | 两项自述事实；公里/分钟类型及单位校验；同一条记录，不重复计跑步天数 |
| “体重69”且已设默认kg | 使用已授权字段单位并在回执显示69kg；无默认单位则问一次 |
| “吃了一碗牛肉面” | 用餐是自述事实；热量/营养属于估算，不能冒充实测或反推精确食材重量 |
| 含“计划/如果/听说/举例”的语句 | 不作为已发生事实；疑义时问“这是计划还是已完成？” |
| 缺少必填真实字段 | 追问或保留候选，不能用0代替未知 |
| 模板/绑定被另一页面修改 | 409/428，保留自然语言草稿、原映射与差异，明确采用后重提 |

营养估算使用独立`estimated_values`注解，附方法/来源/不确定性，不塞进权威实测字段。默认不参与任务、成就、奖励；用户可单独开启“含估算的营养趋势”，图表持续标“估算”。确定性单位换算可作为真实字段的标准化值，保留原单位和换算依据。

## 6. 每日/周/月报告

三类报告分别有开关、时间、时区、覆盖周期、模块范围；设置也可以用自然语言完成。默认自动报告关闭，不因普通聊天自动产生持续收费任务。

| 类型 | 建议启用默认时间 | 默认统计范围 |
| --- | --- | --- |
| 日报 | 次日08:00 | 前一个完整当地自然日 |
| 周报 | 周一08:00 | 上一个完整周一至周日 |
| 月报 | 每月1日08:00 | 上一个完整自然月 |

用户可选择“当天22点总结今天”等截至运行时的报告，必须标注“截至22:00，周期未结束”；不能把它伪装成完整日/周/月。周几、每月几号均可设，短月份的31号按当月最后一天执行；每类最多一个启用日程。人工“生成今天/本周/上月报告”不受自动开关限制。

报告首屏：一句总结、实际进展、需要关注、下一步建议。展开后有数据卡、来源、覆盖率、统计口径和生成版本；建议不自动修改既有任务，需明确“采纳建议”。

规则：

- 数字由数据库快照计算，AI只分析事实包；区分0/无记录、目标/实际、自述/估算、有效/待复核授予、发放/冲正净额。
- 报告原始合计使用权威记录，不用趋势图长粒度日均冒充累计值，也不让视图排除影响权威统计。
- 没有记录时生成“本周期未记录”的确定性空报告，不编造表现或继续花钱生成长文；不把无记录解释成没行动。
- 报告保留原快照和版本。补录后显示“数据已更新，可重新生成”，不覆盖历史原文；同快照的重复请求复用已有结果。
- 电脑关机、Docker停止或断网时不能准点生成。恢复后按设置最多补最新一期，不批量补几个月；通知范围仅应用内。
- 关闭日程后停止未来队列，当前已发出请求尽力取消，已发生API费用不可承诺退回；应用内明确区分自动任务和用户手动请求。

## 7. 面板交互改造清单

| 位置 | 默认可见 | 默认隐藏/高级入口 |
| --- | --- | --- |
| 首页 | 聊天输入、短回复/计划/记录/报告卡；原标准/极简切换 | 运行日志、JSON、token统计、绑定与算法 |
| 新建任务 | 一行“你想做什么”，发送，示例提示 | 类别/阈值/模板/时区/颜色等完整表单 |
| 任务列表 | 名称、下一步、截止/节奏、自然语言进度 | 数值验收表达式、奖励策略、实例/模板版本 |
| 新建记录 | 一行“发生了什么”，必要补问卡 | 原字段表单、任务关联ID、发生时间技术格式 |
| 数值 | 用户固定的少量重点指标和“问问我的变化” | 全部指标、粒度/异常筛选/聚合配置 |
| 成就 | 近期达成、下一里程碑、系列进度 | 门槛表达式、规则/授予ID、复核审计 |
| 个人信息 | 少量概况和“更新我的信息” | 字段类型/单位/模板绑定、来源技术信息 |
| 设置 | AI连接、自动执行偏好、报告日程、显示、数据与隐私 | 高级手动设置和诊断；不显示数据库字段名 |

旧表单保留为“高级手动设置”，AI不可用时能直接进入。后退、关闭弹窗或切路由保留自然语言输入；手机可在输入未完成时离开再继续。关键状态采用文本，不只用颜色或动画。

为v0.4准备：会话、计划、记录回执、报告和追问卡有独立ViewModel；业务API不返回HTML。服务端负责实体/状态，前端Presenter负责文案与布局。v0.3不引入新前端框架、皮肤系统或大范围样式重写。

## 8. AI接入、费用与数据边界

第一家供应商沿用DeepSeek，密钥仅在服务端。模型、能力、输出方式和上下文上限可配置；不硬编码旧deepseek-chat名称或假定所有模型支持同一格式。本轮核对官方文档仅用于接口设计，不访问用户API账户。

首次连接卡一次说明“会将所选模块的必要内容发给DeepSeek”，同时选择可读范围与用量限制；之后在同范围内不反复打断操作。扩大范围、启用定时报表或更换供应商时再明确确认具体变化。

JSON Output、Tool Calls与strict能力不同，格式合法仍需本地Schema、引用、业务及权限校验。普通动作与奖励报价分离；上下文不包含登录口令、Cookie、密钥、.env、Codex聊天记录或未授权全量个人历史。

默认限制包括：交互并发1、报告并发1；按任务类型限定上下文、模型调用轮次、超时、输入/输出token和每日作业数。超限显示可重试时间，不偷偷切到更贵模型。费用估算和实测用量分开，不把供应商缓存命中当本地数据授权。

长期分析先用SQL统计+不可变事实快照+分层报告摘要，检索文字再加PostgreSQL全文检索；RAG作为按需增强端口，不是数值统计和事实来源。首版不装向量库，不把全部记录每次塞给模型。
