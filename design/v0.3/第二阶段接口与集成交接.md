# 第二阶段接口与集成交接要求

日期：2026-10-21。状态：待实施补充，配合[第二阶段任务](第二阶段开发规划.md)使用。原[完整AI契约](AI接口与数据契约.md)、5份机器Schema和既有可靠写入约定继续有效；以下补齐实施分层和第三阶段可测试的接口出口，不表示端点已实现。

## 1. 每条工作流共用的链路

`用户输入 → 消息/追问 → 授权上下文 → 按用途结构化模型输出 → Schema/来源/规则校验 → 冻结候选 → 策略 → 领域事务/作业入队 → 回执/轮询 → 类型化卡片`。

不能新增一个“AI记录直接INSERT数据库”的旁路，也不能用模型自己的“已完成”文案作为业务结果。保留阶段一的操作键、有效意图、剩余执行预算、对象/绑定版本和撤销指纹。

### 完整动作接入矩阵

| 动作 | 主要执行目标 | 权限/确认与回执 |
| --- | --- | --- |
| `goal.create` | 目标及计划版本 | 明确小规模新增可自动，回执有实际目标/计划引用 |
| `module.create` | 新模块 | 不扩大已授权云读取范围；关联动作通过local_ref编译 |
| `record_type.create` | 相容记录模板 | 不静默改变旧事实Schema |
| `metric.create` | 指标定义 | 当前值只能来自确定性重算 |
| `task_template.create` | 任务模板及必要当前实例 | 独立报价后锁价，未开始可无当前实例 |
| `task_template.change` | 下一有效定义/计划新版本 | 仅未来生效；批量覆盖需整组确认，锁定实例不变 |
| `achievement_series.create` | 系列及门槛 | 不写已授予状态；历史纳入单独确认 |
| `record.create` | 真实记录/来源/估算注解 | 明确完整事实可自动，默认最多5条；回执列实际值与影响 |
| `record.correct` | 来源版本的新修订 | 整组差异确认；未修改字段来源保留，重算/冲正不重复 |
| `profile.patch` | 静态字段或统一观测写入 | 观测走事实链、派生拒写，绑定指纹/资料版本必验 |
| `report.generate` | 持久报告作业 | 只入队和分析，不修改事实；按需与自动开关独立 |
| `report_schedule.change` | 日/周/月日程 | 启用或扩大收费需确认，关闭不额外确认；卡片含下次运行 |

编译器引用注册表须覆盖`module_ref/goal_ref/record_type_ref/template_ref/record_ref/field_ref/task_refs`，并验证类型、用户、模块、版本和状态。沿用规划阶段“其他引用位置一律拒绝”的实现会阻断新动作，不能只扩白名单。

新记录、配置、纠错混在同一相互依赖方案时，整组采用最高确认等级；某个依赖动作非法则不应用该组。报告分析等外部作业通过同事务outbox持久化，提交后单独执行；后续报告失败不回滚或重复创建已保存事实。

## 2. 字段来源和追问证据

- 为原消息及每次追问回答提供稳定`source_ref`，保存原文、接收时间、run/消息归属及内容hash。可用`message:<id>`和服务端分配的回答引用；不得让模型自建证据。
- 当前实现的`detail.answers`只是一组字符串，扩展事实抽取时必须补齐稳定证据身份及解析器；不能把回答中的数值错误引用到不含该值的原消息。
- `user_statement/authorized_context/unit_conversion`真实字段逐项匹配源片段和模板类型。单位换算保存原单位/公式；`ai_estimate`只能进入独立估算注解。
- 发生时间保存精度及解析依据；相对日期首次冻结、重试不漂移。纠错只改值时保留原时间元数据，明确改时间时同时重算精度/依据；必要的DTO补充在P2-00同步Schema。
- `profile.patch`也须验证实际值来自当前自述或已授权事实，不能因为有一个合法`evidence_ref`就允许模型把任意推断写入个人资料。
- 事实自动执行的授权识别单独实现，不能继续只使用阶段一`explicitCreation`判断“记一下”；问答、假设、引用和最新回复中的限制仍优先。

## 3. 公共HTTP接口完成清单

沿用`/api/v1`、登录会话和Origin校验；业务写请求有UUID操作键及必要版本，同键异包409。候选确认与直接表单共用领域服务。

| 路径 | 第二阶段出口 |
| --- | --- |
| 既有会话/messages/runs/proposals/applications | 完整12动作、记录/资料/计划调整/日程/报告投影与正确撤销；不另造第二聊天API |
| 既有records、profile/observations、profile、task-templates等 | AI与高级手动复用同一领域写入口和查询结果 |
| `GET /ai/config`、`GET /capabilities` | 对齐已实现/已启用/已配置/已授权；任务生成等旧false标记不能与新planning能力矛盾 |
| `GET /ai/usage` | 增加用途/父子作业关联的实际与unknown用量；不返回密钥和原始供应商载荷 |
| `POST /reports/generate` | 验证既有ReportGenerateInput，返回202和可查询的报告/修订/作业身份 |
| `GET /reports` | 用户归属、kind/周期/模块筛选和分页；列当前修订/状态/覆盖率 |
| `GET /reports/:id` | 排队/生成/成功/失败/过时投影，修订、事实来源、分析和最后错误；无读写混用 |
| `POST /reports/:id/cancel`（补充） | 取消指定待完成修订，版本及操作键保护；已发布结果如实返回，不能假称撤回外部费用 |
| `GET /report-schedules` | 三类独立配置/关闭默认值、版本、next_run_at和暂停原因 |
| `POST /report-schedules/:kind/preview` | 配置与版本→周期/下次时间/范围/费用约束摘要及一次性令牌 |
| `PATCH /report-schedules/:kind` | 同一服务校验令牌/版本后保存，关闭无需重新授权收费 |

P2-00须为新响应、取消请求、列表查询及卡片补机器Schema和OpenAPI；列出的逻辑字段若与原Schema不能兼容，显式修订，不依赖`any`放行。

### 报告作业推荐统一响应

直接调用报告入口后，应已有持久报告身份与修订，不能只得到一段无法查询的临时字符串：

```json
{
  "data": {
    "schema_version": "report-job/1.0",
    "report_id": "90000000-0000-4000-8000-000000000101",
    "revision": 1,
    "job_id": "90000000-0000-4000-8000-000000000102",
    "status": "queued"
  },
  "operation_id": "90000000-0000-4000-8000-000000000103"
}
```

这是P2-00待固化的响应样例，不是现有运行接口。前端用`GET /reports/:id`查指定修订与job状态；聊天入口的`TurnResponse.report`投影到同一报告身份。无需为直接报告请求伪造一条用户自然语言消息来满足`ai_runs.message_id`非空约束：报告使用自己的持久`report_jobs`，通过父意图/operation关联共用预算和worker基础。

`queued`不等于报告已生成。建议沿用现有报告状态`queued/generating/ready/failed/outdated`；取消未发布修订用明确`CANCELLED`错误和可见文案，若另增状态必须同步TurnResponse和卡片Schema。历史修订不可被新的失败覆盖。

报告幂等分两层：操作键防请求重放，报告身份/快照hash/分析版本防重复发布。已有同快照结果复用时显示它实际的截止时间；不能把旧报告伪装成分析至新时间。显式再生成才产生新分析修订。

## 4. 报告、日程和报价的后端边界

| 服务 | 必须做 | 不应做 |
| --- | --- | --- |
| ReportFactsService | 一致性SQL快照、周期边界、去重/覆盖率、来源引用 | 用趋势桶均值或模型总结算真实总量 |
| ReportNarrativeService | 校验report-narrative、fact引用/定量占位、分析修订 | 接受模型自造数值表、自动执行报告建议 |
| ReportJobService | 唯一身份、lease/有限重试、发布回执、取消 | 为重复HTTP重新发起无限付费调用 |
| ReportScheduleService | 独立开关/时间、确认、逻辑时刻、有限补生成 | 用浏览器定时器当唯一调度器或外部cron表达任意命令 |
| RewardQuoteService | 既有批量reward-quote/1.1、规则hash/类别上限/锁价 | 将金额字段开放给普通AI动作或用户编辑 |
| QueryContextPort | 先SQL时间/模块查询、再受限摘要检索，来源版本/授权校验 | 读未授权模块，靠相似向量代替统计 |

每次供应商调用均记录purpose、parent_operation/run/job、attempt、schema/prompt/model版本、预留/实际/unknown用量；所有用途归入同一用户日预算。并发先保持全局一个供应商调用执行槽，报告与交互各自排队，交互优先且报告不能永久饿死；后续放开并发必须有同预算竞争测试。

## 5. 第三阶段API测试准备

第二阶段须交付一个默认关闭、只使用合成测试用户/数据库的真实API入口，并分用途输出：

| 测试组 | 最少覆盖 |
| --- | --- |
| plan/chat | 目标规划、必要追问、改为只预览/取消、未来调整 |
| extract | 完整事实、缺字段、单位/日期、计划/事实区分、估算分离 |
| profile/correction | 个人观测更新、旧记录定位/纠错、差异确认及来源校验 |
| report | 三类真实分析、fact引用、缺失/0、空数据不调用、修订与建议不执行 |
| schedule | 自然语言日程配置及确认；真实供应商调用前后关闭竞态，时间穷举仍用注入时钟 |
| reward_quote | 单批1～4任务、有效金额/规则hash、失败回退与未来锁价 |
| protocol/failure | 鉴权/额度/429/超时/截断/无效JSON/unknown usage、幂等/取消/重启 |

真实供应商无法可靠制造的429、半响应和网络未知用协议模拟故障注入，不能为得到错误码反复烧真实额度。第三阶段结果分别记录离线协议、真实模型、浏览器、实机，未执行就是not_run。

运行前检查完整配置与明确开关，设置每组最大请求数/token与整套总上限，使用`preview_all`起步；合成数据可应用以验证完整业务链，但禁止写开发库。输出脱敏结果与usage，不输出真实密钥、Cookie、完整私有上下文或推理原文。

## 6. 代码冻结交接材料

第二阶段出口的`v0.3/docs/phase2/`至少包含：接口完成表、能力矩阵、验收结果、配置模板（无密钥）、迁移/备份版本、可复现源码清单、提示词/Schema版本、测试输入及第三阶段实际执行顺序。第三阶段无需阅读整段Codex历史即可启动。

首轮真实联调顺序：连通/权限/用量 → plan与extract → correction/profile与复合写入 → report/reward_quote → schedule及重启/关闭 → 浏览器/手机/升级恢复。发现越权写入、重复事实/账本、虚构报告数字或预算绕过时停止该能力的后续真实调用，保留证据并修复。
