# v0.3 Harness 收口与迁移评估

2026-11-27。建议先修现有 TypeScript Harness 的预检、纠错和诊断，再用合成数据评估 SDK。业务规则、权限和写入仍由人生面板服务端负责。本文记录 v0.3 修复前的诊断。当前状态见[缺陷清单](../../log/v0.3/现阶段Bug与处理清单_2026-11-27.md)，后续任务见 [v0.4 Harness 开发规划](../v0.4/Harness开发规划.md)。

## 本次故障的证据

本机 13:11:05 开始的规划作业记录了 **1 次 `deepseek-flash` 调用，供应商用量已收到**。13:11:35 作业以 `INVALID_RULE` 结束，未生成提案或应用回执。事件只记了统一错误码和提示，失败作业没有保留模型原始回复，所以这一次具体是哪条规则冲突无法确定。核对仅查询状态、计数和字段是否存在。

现有流程在模型返回后先做 JSON Schema、引用等编译检查。这些检查失败可触发一次自动修正。随后，循环外的事务预检才检查任务验收规则。因此，一份输出可以通过 JSON Schema 和编译，却在预检被拒后直接结束。所有 `INVALID_RULE` 又映射成同一句话，甚至目标字段或记录数量也共用该提示。相关入口是 `apps/api/src/ai/service.ts` 的 `tick`、`validateBatch`，以及 `apps/api/src/phase2-tasks.ts` 的 `validateTemplate`、`validateMeasure`。

使用与当前部署相同的镜像、无网络的临时数据库和模拟模型重现如下。模拟模型的第二次响应会恢复合法输出。

| 合成响应的首个问题 | 当前结果 | 目标行为 |
| --- | --- | --- |
| 手动验收任务却带记录规则 | 1 次调用，`INVALID_RULE` | 明确指出冲突，允许一次保留用户语义的修正 |
| 要求记录验收却没有规则 | 1 次调用，`INVALID_RULE` | 可推导时有限修正。缺少真实验收标准时向用户追问 |
| 阈值为零 | 1 次调用，`INVALID_RULE` | 不能把零静默改成一。可从原话确认的值才允许模型修正，否则追问 |
| 上下文引用错误 | 2 次调用后进入预览 | 保留现有纠错，并检查重试按次数和预算记账 |
| 有效方案 | 1 次调用进入预览 | 保留首轮成功路径 |

上述失败均无业务写入。合成复现只证明这些情况会走同一条失败路径，没有反推出用户那次的具体字段。复现结果在本机部署目录的 `harness-review/reproduce.log`。本轮未重新调用供应商或修改生产业务状态。

## 下一阶段交付顺序

| 顺序与范围 | 实施任务 | 完成标准 |
| --- | --- | --- |
| **P0 · 先修任务规划** | 在模型契约和提示中明确 `manual → rule:null`，`record_optional/record_required → rule:对象`，提供一例手动勾选和一例记录时长。记录规则使用同模块已授权记录模板，数值字段与单位一致，阈值为正。为任务创建及修改复用同一领域校验，修改按合并后的配置验证 | 当前三个合成失败可分别定位。给定明确需求时，有预算则至多修正一次并进入预览。信息缺失时返回具体问题，不能制造阈值、单位、目标或事实 |
| **P0 · 调整校验顺序和失败分流** | 模型响应 → 解析/编译 → 回滚式领域预检 → 再做报价、预览或落库。可修正的候选错误进入现有重试环，保留最大两次规划调用与现有预算。修正提示作为独立的服务端元数据传递，避免混入用户提供的回答或授权证据。预检事务结束后才允许下一次网络调用。最终写入保留事务内的授权、版本与来源重查 | 格式合法但业务无效的候选不落库。撤权、取消、过期、模型参数拒绝及预算不足不会因此再发请求。确认后只产生一份原子回执，账本行为不变 |
| **P1 · 错误分型与页面提示** | 记录校验阶段、动作类型、字段路径、原因码、尝试次数和模型版本。用户消息改为可处理的提示，如“这个任务需要记录验收，但没有指定用哪种记录判断。你希望手动勾选，还是按学习时长验收？” 对外只暴露白名单字段，不写原话、记录值、完整候选或密钥到诊断日志 | 同一句泛化报错不再覆盖所有失败。日志可区分供应商失败、编译失败、业务预检、权限改变和用户需回答的问题 |
| **P1 · 记录、报价与报告回归** | 把明确的失败分流复用于记录、资料、报价和报告，但各自保留权限和事实规则。长期报告继续从 SQL 事实快照取数。用现有日预算、调用截止时间和父意图总调用上限，排除 SDK 隐式重试 | 假设不生成真实记录，纠错需确认。报表数字可回溯，重复提交、撤销、日程取消或授权改变都不会造成重复写入、发币或额外外呼 |
| **P2 · 真实模型验收和迁移实验** | 先跑离线用例，再取同一批中文合成需求对照旧版和新版。规划覆盖手动、按时长、按次数、缺条件、相同名称多模板、任务调整及“只预览”。另测录入、纠错、日报/周报/月报和日程。定好真实调用额度后再跑供应商，保留每个用例的通过条件 | 比较首轮有效率、最多两次内的有效率、澄清正确率、调用次数和 p50/p95 延迟。业务错误路径零部分写入、零额外发币。总样本数与失败原因可查，少量线上样本不作为稳定性结论 |

首个合并项建议可单独发布，只把任务规划的错误从“判错就结束”改成“可修则一次修正、缺信息则追问”。真实测试可扩展现有 `scripts/real-api-phase2.ts`，并用空白数据库及合成内容。若加入缓存统计，应读取供应商的 `prompt_cache_hit_tokens`、`prompt_cache_miss_tokens`，与现有输入/输出 token 分开。缓存省下的量以同一模型的对照结果为准。[DeepSeek 缓存文档](https://api-docs.deepseek.com/guides/kv_cache/)

## GitHub 候选及迁移判断

| 仓库 | 与现有系统的接点 | 迁移取舍 |
| --- | --- | --- |
| [官方 DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) | MIT，Cordis 插件架构。官方 TypeScript SDK 可以通过 stdio JSON-RPC 启动并驱动独立 `dsh` 进程，含 `sdk-minimal` 配置可供评估 | **适合隔离实验，整体迁移收益低。** 生命周期、权限、会话、工具和诊断要单独接入及审查。项目还在开发者预览，接口可能出现破坏性变更。若试验，只返回提案，不绑定 PostgreSQL 或生产密钥库，不挂宿主机目录或通用工具。[SDK](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/sdk) · [运行时架构](https://deepseek-harness.github.io/deepseek-harness/en/reference/) |
| [Vercel AI SDK](https://github.com/vercel/ai) | TypeScript 原生，有 `@ai-sdk/deepseek`，可以直连供应商。结构化输出 API 与现有 `Gateway` 接口的职责接近 | **改造供应商适配层的成本最低。** 后续确实要接多模型时优先做 PoC。仍需确认目标模型的输出模式、用量字段、超时取消、官方端点限制和实际重试次数。[DeepSeek 适配器](https://github.com/vercel/ai/tree/main/packages/deepseek) · [结构化输出](https://github.com/vercel/ai/blob/main/content/docs/03-ai-sdk-core/10-generating-structured-data.mdx) |
| [Pydantic AI](https://github.com/pydantic/pydantic-ai) | 可参考输出验证失败如何返回可修复反馈，以及如何划分重试预算 | **参考设计，不引入运行依赖。** 目前服务端和领域验证均在 TypeScript，引入 Python 会增加部署与接口维护成本。[输出验证](https://github.com/pydantic/pydantic-ai/blob/main/docs/output.md) · [重试](https://github.com/pydantic/pydantic-ai/blob/main/docs/retries.md) |
| [DeepSeek Harness macOS Wrapper](https://github.com/Starmadebydata/deepseek-harness-macos) | 社区版 SwiftUI 外壳，主要负责启动本机 `dsh web` 并展示界面 | 可参考将来 macOS 桌面入口。它依赖底层 DSH，自身不提供人生面板需要的服务端任务校验 |

DeepSeek 当前 `json_object` 能约束 JSON 输出格式，记录模板是否真实存在、字段单位是否匹配，以及用户是否授权仍需本机判断。官方也提供严格模式的工具调用，使用 Beta 端点及其支持的 Schema 子集。可以用只返回候选的工具做对照实验，仍需运行现有校验器和事务预检。[JSON Output](https://api-docs.deepseek.com/guides/json_mode/) · [Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)

迁移决策放在修复完成后。候选实现通过同一套用例，且在首轮有效率、实际成本或多供应商维护上有可测收益，才考虑接入 `Gateway`。若采用 DSH，固定 SDK 与运行时版本，以独立的最小权限进程只生成候选。评估仅用合成数据和受限临时密钥。验收须证明它不会额外发请求、不会扩大信息范围，切回原适配器也不需要转换应用数据库。
