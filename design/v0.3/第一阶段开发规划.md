## 1. 本阶段交付什么

用户在主页输入“帮我安排未来30天每天学英语20分钟，并设置坚持成就”，系统应在已有授权模块中复用或创建记录模板，形成目标、主线/每日任务、累计时长指标和累计不同日成就系列。通过校验的明确小规模新增自动应用，展示真实回执和对象跳转；有关键缺项则追问，选择先预览或超过自动上限时只确认整组一次。

本阶段不要求AI录入学习事实。用户仍可通过高级手动表单记录学习20分钟，验证新建指标、任务、成就和原系统奖励正常联动。AI绝不能因生成了计划就写入“已学习20分钟”。

| 纳入第一阶段 | 后续阶段实现 |
| --- | --- |
| 独立v0.3环境、公共契约、DeepSeek网关与配置/用量 | 第二阶段：AI记录/纠错、估算、资料更新、新模块创建、未来计划自然语言调整 |
| 会话持久化、后台作业、追问、SSE/轮询与刷新恢复 | 第二阶段：三类按需报告、AI独立奖励报价、其他面板入口简化 |
| 新目标→模板/指标/四类任务/系列成就，支持复用已有对象 | 第三阶段：报告日程/调度、长期统计与摘要检索、整版验收发布 |
| 任务有效期/适用星期、自动/预览策略、原子应用、补偿撤销 | 不在本版：3D/兑换、原生应用、VPS同步、v0.4视觉重做 |
| 首页与新建任务一句话入口、手动降级、备份与回归 | 第一阶段不会把尚未实现的动作偷偷丢弃后部分执行 |

四类任务为主线、每日委托、周常委托、月常委托；按目标需要生成，不强制凑齐。成就默认累计不同日期，明确要求“连续N天”时说明支持范围并追问替代方案。

## 3. 本阶段协议与能力范围

### 3.1 动作白名单

仅开放下列五种动作类型，可组成一个有依赖的方案：

| 动作 | 支持与限制 |
| --- | --- |
| `goal.create` | 保存原意图、目标期限、成功标准与来源；不写完成状态 |
| `record_type.create` | 在已有授权模块创建新模板；先找相容模板，不修改旧模板的事实Schema |
| `metric.create` | 绑定新/已有相容模板和字段；不允许设置当前数值 |
| `task_template.create` | 四类任务、验收规则、颜色、有效期/每日适用星期/偏好时间；不带可编辑奖励 |
| `achievement_series.create` | 从启用后事实计算里程碑；不得直接解锁，不纳入历史补授予 |

可问答/追问而不写入。完整设计中其余动作第一阶段返回未开放能力；一个依赖组含未开放动作时全组不应用，保留输入并说明原因，不执行其中“恰好能做”的一部分。

自动上限沿用产品设计：12个配置对象、4个任务模板、2个指标、1个系列/最多5级，硬上限20个动作。共用一个计数函数：目标、模板、指标、任务模板、系列及新增里程碑计入配置对象数，计划关联元数据与派生任务实例不重复计数。超过自动上限但在硬上限内走整组确认；超硬上限拒绝并建议缩小方案。

第一阶段奖励使用继承的v0.2系统规则及原policy版本，如实标识系统定价；不伪装为AI报价。第二阶段上线AI报价后仅未来新规则版本适用，不能回改已锁实例。

- **依赖：** P1-01、P1-02。

### P1-04：会话、worker与可恢复状态

- **依赖：** P1-02、P1-03。
- **修改范围：** 新增`apps/api/src/ai/`、`apps/worker/src/`、worker启动配置与会话路由。
- 消息写入后返回202；用户/路由/操作键/完整载荷及同会话`client_message_id`双重防重，同键异包409。
- PostgreSQL队列以lease、心跳、有限尝试领取；模型网络期间不持用户锁。同会话串行处理，其他会话不能串用候选或追问。
- 持久化状态版本和单调事件ID，支持SSE重连与GET轮询恢复；进程重启先查本地回执/阶段，再恢复，不能重新创建已提交业务对象。
- 实现最小追问及原run继续、取消、过期/冲突状态；取消已提交操作返回实际结果，不显示已回滚。
- **出口：** 页面刷新、SSE丢事件、worker中断、提交后丢响应、连续重复点击均可恢复且不重复写入。
