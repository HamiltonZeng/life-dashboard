# v0.3 技术实施与验收规划

日期：2026-10-20。状态：设计交接；尚未开始开发或创建v0.3运行环境。本轮不分派其他agent、不迁移18080。

2026-10-21实施状态补充：上述状态与“现有缺口”表保留设计时快照；阶段一现已实现并[收口复核通过](../../v0.3/docs/phase1/收口复核_2026-10-21.md)。按用户新要求，报告调度、长期统计/摘要检索及所有主功能代码归入[第二阶段](第二阶段开发规划.md)，第三阶段集中真实API/整版测试，不再以旧阶段划分延后主功能。

## 1. 技术延续与服务划分

保留TypeScript/Fastify/PostgreSQL/Docker与现有Web。新代码在v0.3独立目录/分支承接6ccc4a1，先配置独立项目/端口/私有库；共用只读依赖和已缓存镜像，本版缓存均在自己的.runtime。不因AI接入直接引入LangChain、Redis、向量数据库或新前端框架。

| 组件 | 职责 |
| --- | --- |
| ConversationService | 会话/消息、受理幂等、追问、可见消息与事件；不执行任意模型指令 |
| ContextBuilder | 读取授权模块、目标、模板、相关事实/报告，固定时间与版本；最小化上下文 |
| ModelGateway | 统一purpose/model/结构化输出/超时/用量/脱敏；旧Blueprint适配器保留 |
| ProposalCompiler | 将ai-decision编译为领域动作，解析local_ref依赖、补稳定ID、校验来源与规则 |
| ExecutionPolicy | 依据用户请求、入口意图、配置和动作影响决定自动/追问/确认；模型不能自授权限 |
| ApplicationService | 单事务、用户锁、前提、领域写入、重算、回执、补偿撤销 |
| ReportFactsService | 生成一致性统计快照、覆盖率和可追溯事实包；不依赖模型算数 |
| Scheduler/Worker | 持久队列、lease、限额、错过调度、后台报告和重试；同库无额外中间件 |
| Presenter | 把服务器DTO渲染成追问/计划/记录/报告卡，为v0.4替换视觉层准备 |

模型调用在数据库事务外执行。快照读取采用REPEATABLE READ；提交时只锁所需用户/对象并重验。请求重放、后台重试、页面恢复共用同一run/application身份。

## 3. 建议数据模型与新增迁移

0001–0004保持不可变，v0.3新增迁移编号从0005起，由单一集成人分配。下面是概念设计，不是已创建表。

| 表/对象 | 核心数据与约束 |
| --- | --- |
| goals / goal_revisions | 目标、原意图、起止/成功标准、模块/版本/状态、原始消息与规划约束 |
| plan_versions / plan_objects | 不可变方案版本、替代关系、对象映射与来源；目标→模板/指标/成就关联 |
| ai_conversations / ai_messages | 用户归属、入口、可见文本/卡片、message_id；密钥不入消息上下文 |
| ai_runs / ai_run_events | operation_id/request_hash唯一、阶段/版本/lease/attempt/用量/取消、单调event_id |
| ai_context_snapshots | 授权范围、引用版本/指纹、时间锚、摘要与hash；不存登录秘密 |
| ai_memory_items | 用户已表达目标/约束的简短记忆、来源与修订/失效状态；模型推断单独标记，不能当自述事实 |
| ai_proposals / ai_applications | 冻结候选/风险/前提/版本、稳定ID映射、事务回执、补偿状态 |
| record_provenance / record_estimates | record_id+version+字段、用户片段/换算/估算方法；不把估算伪装实际值 |
| report_schedules / report_jobs | 用户+kind唯一、版本/开关/范围/下一运行；job逻辑时刻唯一、锁/取消/尝试 |
| report_snapshots / reports / report_revisions | 周期身份/范围、不可变事实包/hash、源版本、模型/提示版本、分析与过时状态 |
| reward_quotes | 服务端报价身份、模板规则hash/版本、金额/上限/来源/provider/model/校验/回退；普通候选不可写 |
| task_templates调度扩展 | active_from/until、daily weekdays、偏好时间、goal/plan版本；既有实例快照不改 |
| ai_usage / ai_budget_reservations | 按user/purpose/run/attempt记录预留、实际用量/未知状态；防重复作业绕过预算 |

身份/外键包含user_id；不能仅凭客户端ID连接对象。保留计划和来源修订，不删除已引用的模板。单次计划撤销以归档/补偿处理，保留事实与奖励审计。

备份范围：用户目标、方案、会话可见内容、已采纳候选/应用回执、来源、日程、报告快照/修订、报价与用量纳入版本化导出；密钥、临时lease、Cookie、运行进程状态不导出。原始模型请求可含私密数据，默认不作为普通导出内容；按显式诊断策略短期保留并脱敏。恢复后需要重置运行lease，不能自动重放所有收费作业；日程恢复默认暂停并展示待确认下次运行。

## 4. 后台调度可靠性

建议一个轻量worker进程/容器，PostgreSQL作为作业存储；轮询约30秒，FOR UPDATE SKIP LOCKED领取，持久lease/心跳/最大尝试数，过期可恢复。网络调用期间释放锁。

各类报告启用/修改后在同事务计算下次逻辑时刻和调度版本；唯一键保护同一期。关闭后禁止新自动调用，作业在调用前和发布前复查日程状态/版本；手动请求用独立source=manual，不被自动开关误取消。

关机/断网恢复：latest_only最多补每种最新一份，skip直接安排未来；多次恢复和时间回拨不无限补生成。DST重复时刻只运行一次，不存在时刻顺延；短月落月底。服务器储存UTC边界与原时区，用户改时区只影响未来。

“每个逻辑任务只发布一次”由本地事务保证；供应商未知网络结果不保证只计费一次。重试前查询本地作业状态，分开记录预算预留、已知用量和未知尝试，达到上限暂停。报告发布后可由应用内卡片提示，不加入邮件/聊天平台发送任务。

## 5. DeepSeek、上下文与成本

优先复用现有fetch/错误处理，新增purpose=chat/plan/extract/report/reward_quote；模型ID和协议由配置/能力探测决定，测试固定实际返回版本。第一版支持稳定JSON Output，严格工具Schema可后续按能力启用；canonical Schema不会直接假定兼容供应商Beta子集。

建议初始运行预算（工程默认，实施时压测调整）：交互同时1个、报告同时1个；单模型尝试60秒、整个交互作业180秒；每个意图最多2轮受限上下文工具、最多一次格式修复，全部调用共享作业预算。超过预算返回追问/失败，不能让模型无限自循环。前端及时显示已受理/处理中，而非让HTTP一直等待。

简单抽取/普通报告优先低延迟模型模式；复杂规划按需用较强模式。不要每次重新选择模型和生成整套全部模块；保留稳定系统提示/Schema前缀，动态事实置后，只带相关模块/时间范围/目标。记录供应商实际usage/cache命中，缺失用量标unknown，不用“估计token”冒充账单。

日作业上限与token上限为硬限制；人民币预算若显示估值，要注明价格版本/汇率/供应商价格变更的不确定性，不能声称精确现金硬停。无需本轮填写价格或兑换率；未配置货币预算时只展示真实token与作业额度。

长期数据路径：原始事实与修订→可重建日统计/覆盖率→不可变报告快照→日/周/月分析摘要。语义文字检索先用PostgreSQL全文搜索；未来QueryContextPort可以换pgvector。SQL决定数值，RAG只找相关文字，不拿相似向量猜支出总数或完成次数。

长期会话使用已授权目标/约束记忆加最近必要消息，保留source_ref和版本；用户纠正后旧记忆失效，不能让摘要覆盖明确的新指令。模型推断偏好先作为建议，不自动变成个人资料。读取历史报告时其建议仍是数据，不能伪装成新的用户执行命令。

## 6. 独立奖励报价

延续此前确认的v0.3方向：新任务版本可以由AI报价，普通规划动作和用户均不能直接填reward_amount。

服务端在应用事务外构建脱敏规范化任务快照→内部报价模型→校验整数/类别上限/依据/模板规则hash→持久报价→应用事务核验后锁定。用户自填“很困难/很重要”不能绕过类别额度。

首版建议金额上限沿用v0.2类别候选金额100/10/50/200、额度仍每月1/每天3/每周3/每月2；AI在允许范围内给正整数，规则版本明确。额度、补录期、资格保留、冲正/恢复和历史不补发继续由服务器计算。普通聊天“奖励99999”无效。

相同模板规则版本复用已核验报价，未来周期实例直接锁定，不在每日物化时调用模型；模板未来规则变更才重新报价。旧实例/旧已发资格不重定价。报价失败可采用明确标识system_fallback的原系统规则以保证任务可用，不能显示为AI报价；策略可配置为等待报价，但不得静默随机金额。

报价请求/响应使用独立内部Schema，不通过公开apply动作写入，模型不获得账本SQL。新增报价引用及未来实例快照如需迁移，补齐全图恢复与旧任务兼容测试。

## 7. 为v0.4准备的前端结构

引入受限接口层：ConversationController、Composer（一行输入/追问）、ActionCardRenderer、PlanSummary、RecordReceipt、ReportReader、AdvancedEditorAdapter。当前原生TypeScript即可实现；业务状态和渲染分开，不提前迁移框架。

ViewModel只包含卡片类型、实体引用、状态、短摘要/差异/来源/允许按钮。模型原文HTML不注入DOM；Markdown转义/链接白名单、无可执行脚本/iframe。服务器不生成CSS或布局。v0.4可替换组件外观，复用同一API、卡片协议和可靠写入流程。

隐藏详细参数不等于删除原能力：高级入口保留阈值/字段/绑定/诊断；AI失败能手动。任务目标与实际进度等对决策有用的数值仍以自然语言显示，不要求用户理解SQL聚合和版本号。
